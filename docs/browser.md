# The browser window

The standalone loot browser is a single non-secure window with two views — **History** (the table) and **Insights** (analytics). `modules/Browser.lua` owns the window shell; `modules/BrowserTable.lua` owns the History table; `modules/Analytics.lua` owns the Insights tab. All three read the same dataset through `Database:ActiveHistory` (see [schema.md](schema.md)), so `/lh test` swaps synthetic data under both views at once.

## The standalone window (standalone-windows)

`EnsureFrame` (`Browser.lua:937`) builds one plain `CreateFrame("Frame", "LootHistoryWindow", UIParent, "BackdropTemplate")` — the Ka0s Standard standalone-windows pattern for standalone data browsers, of which this addon is the reference implementation. It is **non-secure by design**: no `SecureFrameTemplate`, no `InCombatLockdown` gate, so the window opens and repaints freely in combat. (The *settings* panel is separately options-ui-§2 combat-gated; the browser is not.)

The frame is `HIGH` strata, mouse-enabled (no click-through to the world), movable and `SetClampedToScreen(true)` (`Browser.lua:953-956`), and resizable from a bottom-right grip built by `Core.MakeResizable` through the `NS.MakeResizable` seam (`Browser.lua:1058`; on a degraded install, the pre-library grip in `core/CoreSetup.lua`). The grip is bounded at `B:MinWidth()` × `SKIN.minH`, passed explicitly because the library's default floor is the current (700px) height; Lock frame gates it through `canResize = not B:IsLocked()`, which leaves it drawn and inert. Four standalone-windows obligations are wired in `EnsureFrame`:

- **ESC to close** — `LootHistoryWindow` is appended to `UISpecialFrames` (`Browser.lua:1096`), so Escape hides it via the stock path. Because that path calls `frame:Hide()` directly (not `B:Hide()`), an `OnHide` hook closes any open dropdown menu (`Browser.lua:1083`).
- **Persisted position / size** — `SaveWindow` / `RestoreWindow` (`Browser.lua:97-118`) write `settings.window = { point, x, y, w, h }` to the active profile (`NS.db.profile`) on drag-stop and once per resize release (the grip's `onResizeStop`; never per size step, and never after a press Lock frame refused), and restore it on open and on every profile event (`B:AdoptProfile`). Restore floors width/height at the frame minimums (`B._minW`/`B._minH`). This geometry is an architecture-§5 carve-out: it is written straight to the profile, **not** through `Schema:Set` (see [settings-panel.md](settings-panel.md)).
- **Persisted scale** — applied from `settings.windowScale` on build (`Browser.lua:1092`) and live-updated by `OnSettingsChanged` when the scale setting changes (`Browser.lua:1241`), and re-read from the new profile by `B:AdoptProfile` (`Browser.lua:703`).
- **One re-skin seam, and the edge is not its own** — `B:ApplySkin(f)` (`Browser.lua:72`) is the single point every window in this addon wears the Ka0s edge through, and it delegates to `NS.ApplySkin` (`core/CoreSetup.lua`), which is `Core.ApplySkin` on a working install and that file's pre-library copy on a degraded one. The background, 1px black border, 1px gray inner highlight, gold title and gray divider are `Core.SKIN`'s, not restated here (standalone-windows). `Browser.lua`'s own `SKIN` table (`Browser.lua:16`, exposed as `B.SKIN`) keeps only what this addon owns: the two tab-label colors and the layout heights. Everything — window, dropdowns, menus, buttons — is still drawn from the stock `WHITE8X8` texture with no ElvUI dependency, and `ApplySkin` stays separate from construction so a future settings panel can re-skin live; the close control (`B:MakeCloseButton`) no longer draws a glyph of its own: it delegates to `NS.MakeCloseButton` (`core/CoreSetup.lua`), which hands `LibKa0s-Core-1.0` this addon's **folder name** as its third argument so all four windows — History, the export modal, the export copy window and the debug console — wear the collection's shared `close` mark. The old 24×24 class-colored `×` survives only on an install with no LibKa0s, where `core/CoreSetup.lua`'s degraded branch still builds it.

The default height (`SKIN.defaultH = 700`) opens tall enough to show the full Insights view; the minimum height is `SKIN.minH = 460`. The **minimum width is derived, not hard-coded** — `B:MinWidth()` returns the wider of the column-derived table floor (`BrowserTable:MinFrameWidth` — every fixed column width + gaps + the Item column's minimum + scrollbar gutter + margins, so columns can never overflow horizontally) and the toolbar-fit floor (`B:ToolbarSpan()`, the measured dropdown span — see the filter bar below — + gap + a minimum Export button + pane margins). The toolbar floor is taken a second time in `EnsureFrame` once `BuildFilterBar` has measured its labels, and both the resize grip and `RestoreWindow` clamp to that final `B._minW`, so a size saved by a build with narrower controls is widened on load. The old hard `1160` floor is gone. The result is used as both the opening width and the resize floor; the filter bar then **fills whatever width the window has** (below), so the frame floor and the toolbar packing can't drift apart.

## Window shell

### Tabs

The tabs are a **registry**, not a hard-coded pair (timeline-ledger spec §8.0): `B:RegisterTab(spec)` takes `{ name, order, build(pane), refresh(), export(title), filters }` (plus, for a tab that groups its own way, `groups`, `group()` and `setGroup(mode)`; see [Holdings tab](#holdings-tab); and, for the Search autocomplete, `suggest(text)` and `pick(item)`; see [Search autocomplete](#search-autocomplete-p9)), keeps the specs ordered by `order`, and `B:Tabs()` returns the names. History (`order = 10`) and Insights (`order = 20`) register themselves as specs; the Holdings tab registers from `modules/HoldingsTab.lua` (`order = 40`, see [below](#holdings-tab)), and the Timeline tab registers between them from `modules/Timeline.lua` (`order = 30`, see [below](#timeline-tab)). The tab strip lays its buttons out by index, so a tab registered late re-flows it. Each tab is a content pane created up front but built lazily: `BuildPane` calls the spec's `build(pane)` (`B:BuildTable(pane)` for History, `NS.Analytics:Attach(pane)` for Insights, `HoldingsTab:Attach(pane)` for Holdings) only the first time a tab is shown — the panes now hold **only** their view, because the filter bar and footer are shared window chrome (see below). `B:SelectTab` (`Browser.lua:139`) toggles pane visibility, recolors the tab labels (gold active / gray idle), moves the underline, and refreshes the newly shown view against the shared filter — History re-runs `BrowserTable:Refresh` + `RefreshFilterOptions`, Insights re-runs `Analytics:Refresh`, and both then repaint the shared footer. `lastTab` is remembered within a session. `B:Show` eager-builds the History pane so the table (and thus `matchCount`) exists even when the window opens straight onto Insights.

### Filter bar — a browser-wide singleton (issue #13)

The filter bar and footer are **shared window chrome, not per-tab**: one filter drives the History table **and** the Insights charts, so you always know which slice of your loot you're looking at across both views. `EnsureFrame` anchors a `filterHost` frame below the tab strip and above the panes, then calls `B:BuildFilterBar(filterHost)` (`modules/BrowserFilterBar.lua`, split out of `Browser.lua`) once; the footer is created directly on the frame. Layout top-to-bottom is: title bar · tab strip · **filter bar** · panes · **footer**.

`B:BuildFilterBar` lays out a **two-row** bar, ordered to mirror the table's columns:

- **Row 1** — Group-by dropdown · **Direction** dropdown · item-name search box · right-aligned `Save` · `Reset` · `Clear` buttons. Direction lives in row 1, not row 2, on purpose: row 2's dropdown span is the toolbar's **width floor** (`B:ToolbarSpan()`), so a ninth row-2 dropdown would have widened the minimum window by its whole width, while row 1's search box simply absorbs the space.
- **Row 2** — the column filters left→right in table order: Date · Bound · Quality · Type · SubType · Source · Zone · Character, plus a right-aligned tab-aware `Export` button.

**The bar fills the window and scales proportionally** (timeline-ledger P6). The bar host is inset 6 px from each window border, and row 2 spans it exactly, so the right gap always equals the left one. Each row-2 control *i* (the eight dropdowns and Export) has a base width *b_i* — its measured one-line width below, Export its 120 px floor. With *A* = bar width − 8 gaps of 8 px, the ratio is **r = A / Σb_i, floored at 1**; each control is `floor(b_i · r)` wide and Export takes the rounding remainder so the row ends exactly at the right margin. One ratio for every control keeps their proportions (the widest label stays the widest box), and r never drops below 1, so no control narrows below its base. Row 1 sits on row 2's grid: Group has Date's x and width, Direction has Bound's, the Save/Reset/Clear cluster spans exactly Export's x-range (three equal buttons, 8 px gaps, Save absorbing the 0–2 px rounding), and the search box fills between Direction and the cluster. The pure layout is `B._filterBarLayout(widths, barW)`; `B:LayoutFilterBar(barW)` applies it — anchors and widths only, no rebuild, skipped when the width is unchanged, and closing any open dropdown menu first. The window's `OnSizeChanged` (hooked after the resize grip) and `RestoreWindow` call it, so the bar follows a drag live. At the toolbar floor r is exactly 1; when the column floor (`BrowserTable:MinFrameWidth`) is the wider one, r is already above 1 at the minimum width and the margins are still equal.

**Every control label is one line** (timeline-ledger P4). Each dropdown is as wide as the widest collapsed label it can show, measured at build time with its own label FontString (`GetUnboundedStringWidth`) over every **static** label: the static option sets, each `All` sentinel, `Quality: <q>+` for every quality, every bound state and source, and the library's `<Prefix>: N selected` summary (N up to the option count, two digits for a data-driven list). The label is set `SetWordWrap(false)` / `SetMaxLines(1)`, so a data-driven single pick longer than the control (one long zone or character name) truncates instead of wrapping. Widths never drop below the ones the bar shipped with (Group/Date 120, Direction 104, Bound 96, Quality/SubType/Source 100, Type 112, Zone/Character 146), **Direction and Bound share the larger of their two widths**, and Group stays as wide as Date below it. The fit is `B._filterWidths(measure)` in `modules/BrowserFilterBar.lua`, pure given a measurer, so the suite drives it with a fixed per-character width.

Group-by, sort, and Save/Reset/Clear are table-view concerns; they're part of the shared bar but only affect the History table (harmless on Insights). The one exception is the **Holdings** tab, which owns its own group mode: while it is active the Group dropdown offers only its modes and shows its value, and a pick there goes to it (`B:SetGroup` / `B:SyncGroupControl`; see [Holdings tab](#holdings-tab)). Every filter change funnels through `ApplyFilter`, which pushes to `BrowserTable:SetFilter` (keeping `matchCount` + the footer current for both tabs) and, when Insights is the visible tab, re-runs `Analytics:Refresh`. `B:CurrentFilter()` hands Analytics a plain copy of `B.activeFilter` (the exact field shape `Database:QueryList` consumes), so the charts and the table filter by identical criteria.

All dropdowns are **`LibKa0s-Widgets-1.0`**'s flat-skin control rather than Blizzard's `UIDropDownMenu` — the look stays consistent across the whole Ka0s collection and there is no protected-call taint surface. They are built through `core/WidgetsSetup.lua`'s **one factory**, `NS.MakeDropdown(parent, width)`, which resolves the `chevron` and `check` art through `NS.Icon` and hands it to the library as parameters (a vendored library cannot know which addon folder it sits in, and `Media.Icon` needs that name). This file used to *be* that widget: a local `MakeDropdown`, a singleton popup with pooled rows, a click-catcher and six helpers, 208 lines, the collection's third copy of one control. It is gone (`Browser.lua:198`).

The popup is a **process-wide singleton** — one menu, shared by every dropdown in every Ka0s addon that has adopted the major, parented to `UIParent` at `FULLSCREEN_DIALOG`. Exactly one is open at a time across the whole client. Two consequences: the History window is `HIGH` strata and the export modal `DIALOG`, both **below** the popup, so an open menu draws above them — and because the popup intercepts nothing (since LibKa0s v1.13.0 it listens on `GLOBAL_MOUSE_DOWN` rather than showing a click-catcher), an outside click closes the menu **and** lands on whatever is under the cursor on the same press; and every **non-click close path** must call `NS.CloseMenu()`, because the menu outlives the window and no frame's own `Hide()` reaches it. This addon calls it from the window's `OnHide` (`Browser.lua:1083` — also the Escape / `UISpecialFrames` route) and from `B:Hide` (`Browser.lua:1211`, the slash-command close); `modules/Export.lua`'s modal calls it from its own `OnHide`.

With no LibKa0s, `NS.MakeDropdown` answers nil and `B:BuildFilterBar` **refuses to draw the bar at all** (`BrowserFilterBar.lua:213`) rather than building nine buttons that open nothing. `B._dd` stays nil, which every reader downstream already tolerates.

**Bound, Quality, Type, SubType, Source, Zone and Character are multi-select** (`dd:SetMulti(true)`). Clicking values toggles them into the dropdown's `_selected` set and keeps the menu open; the collapsed button summarizes as the "All" label (empty set), the single option's label (one pick), or `"<Prefix>: N selected"` (`UpdateMultiLabel`, the library's). Two rules keep that summary honest against the **data-driven** option lists: an option that reports itself active (`opt.isActive(dd)` — today only the Character dropdown's "Current" preset) names the whole selection outright, and values with no option row are still counted, labeled by their raw value. Without them a selection whose value is absent from the current dataset (e.g. the logged-in character has no loot yet) would count as zero and the button would wrongly read "All" while the table was scoped. Both of those rules are the library's own at Widgets minor 4 — they were ported upstream **from this file**, which is why the adoption lost nothing here. Selected multi-select items get an inline check markup the library splices itself from the `check` path the seam handed it, and options can carry their own color (quality color, class color). There is **no `icon` field on an option**: the library has none and deliberately will not grow one, because it *measures* inline markup in a label instead — so the Character dropdown folds each looter's class icon into the **label string** (`BrowserTable:ClassIconMarkup`, `Browser.lua:349`) and `withAll` takes a sort key so that list still orders by character name rather than by texture path. No option this addon builds carries `opt.glyph`, which is why the seam passes no `glyphFont`: that field is a precondition for a glyphed row, and a proportional face passed for one draws a box. The **Bound** dropdown (`boundOptions`) is data-driven like the others but kept in a fixed logical order (`BOUND_ORDER`: `Not Bound` / `Bind on Equip` / `Bind on Pickup` / `Warbound` / `Warbound Until Equipped`, matching the Bound column's tooltip legend) — only states present in the data are offered, so e.g. `Warbound` appears once some loot is warbound. `Not Bound` uses a `NONE` sentinel that `Database:QueryList` maps to `r.bound == nil`. The **Zone** dropdown (`zoneOptions`) keys on the zone **name**, not `mapID`: one named zone spans many UiMapIDs — every dungeon floor and sub-map has its own — so an id-keyed menu listed a zone once per floor with each entry filtering only part of it. The name is what the Zone column, group-by-zone and the Insights "Top Zones" list already key on. Rows with no captured name share one `Unknown` bucket (the empty string, which is what `QueryList` matches them on) — and a *blank* name buckets with a missing one everywhere, since `NS.Zone` answers `""` before the client has zone text (`groupOf`, `Database:Stats`).

Each multi-select's `onMultiSelect` copies its set into the matching `B.activeFilter` field via `setToFilter` (`Browser.lua:447`) — a fresh copy, never aliased to the live dropdown, so a later toggle can't mutate the filter behind the table's back — then calls `ApplyFilter`, which pushes `B.activeFilter` to `BrowserTable:SetFilter` and updates the footer. The set-vs-scalar shape is what `Database:QueryList` consumes (`Database.lua:526`; a set means membership, a scalar means equality).

The **date dropdown** is single-select (Today / Last 7 days / Last 30 days / Last 90 days / Last year / All); it writes `activeFilter.from` from `NS.Util.RangeFrom(v)` (`Browser.lua:809`). The **search box** writes `activeFilter.text` on every keystroke (case-insensitive substring on item name). Every **value filter — bound / quality / source / type / subtype / zone / character** — is data-driven: `RefreshFilterOptions` rebuilds each from the current dataset (distinct values, prefixed with an "All" sentinel), so the menu offers exactly the values the history contains and nothing it doesn't. Quality (`qualityOptions`) is sorted in quality order and tinted per quality — so Heirloom / Poor / Artifact appear whenever present, and currency tiers appear here too (unlike the Insights "Quality distribution", which stays item-only); Bound (`boundOptions`) keeps a fixed logical order. The only static dropdowns are the two that are *controls*, not data enumerations: **Group by** (the grouping modes) and **Date** (the range presets) — those always offer every option regardless of the data.

**Character scope.** The Character filter is a multi-select dropdown (empty = all players). It matches each row's **holder** (`Util.RowHolder`, inlined in `matchScalarOrSet`; a legacy row's holder is its `char`), not the character that wrote it (timeline-ledger Phase 7, owner decision 2026-10-06): a move between two holders is a loss on one and a gain on the other, so **Character: Current** shows the character's half of a warband withdraw and not the Warband's. On History the list is built from the rows' holders, so **Warband** is offered (under that name, with no class art) whenever a row sits on it. `B:SetCharSet` (`Browser.lua:561`) is the single seam that writes the char filter and mirrors the selection into the dropdown. The window **opens scoped to the current player** — a session-only default applied by `ApplyView(view, "current")`, deliberately *not* part of a saved view — and the dropdown widens it to any character subset. The menu's second entry is a one-click **"Character: Current"** preset (`charOptions`, inserted after the "All" sentinel): it *replaces* the selection instead of toggling into it (`dd.presets`), lights gold when the selection is exactly the current player (`opt.isActive`), and — via the `isActive` rule in `UpdateMultiLabel` — is also what the collapsed button reads in that state, including on a fresh session where the current character has no rows to build an option from.

**Saved views.** A "view" = group-by + sort + the column filters (bound / quality / type / subtype / source / zone) + date + search (but **not** character scope). `B:CaptureView` (`Browser.lua:600`) snapshots it; `SaveView` writes it to the active profile's `NS.db.profile.savedView`, `ResetView` clears it back to `STOCK_VIEW` (`Browser.lua:251`), and `ClearFilters` re-applies the saved-or-stock view. `B:ApplyView` (`Browser.lua:644`) is the single seam that paints every filter field, the table's group/sort, and the resolved filter, then resets scope. Like `settings.window`, `savedView` is an architecture-§5 carve-out persisted straight to the active profile, `NS.db.profile` (the v9 migration moved any stored view there out of `db.global`; [profiles.md](profiles.md)), so a profile switch brings its own saved view. `asSet` (`Browser.lua:456`) tolerates the legacy scalar form so pre-multi-select saved views still load.

**Export (tab-aware, issue #15).** The right-aligned `Export` button routes through `B:OpenExport`, which picks the modal for the active tab. The modal **header names the source tab** — `"Export " .. lastTab` → "Export History" / "Export Insights", and any future tab flows through the same string. Both modes share the same skinned modal (`NS.Export:Open`, `modules/Export.lua`) — a **Data Set** dropdown (**All Data** vs **Current View**) and an **Export to CSV** button — driven by a per-open `config = { title, providers, csv }`:

- **History tab** — exports loot **rows**. Providers: All Data (`Database:Export({})`) and Current View (`BrowserTable:OrderedFilteredRecords`, the filtered records in current sort/group order). Serializer: `Export:CSV`. That CSV leads with `ts` followed by human `date` (DD-MMM-YYYY) and `time` (HH:MM); renamed raw columns sit beside a readable sibling — human `quality` label before `qualityRaw`, formatted `vendorPrice` ("Ng Ns Nc") before `vendorPriceRaw` (copper) — `bound` is the friendly label. Following the vendor columns, the AH-price feature adds the **computed** `auctionPrice`/`auctionPriceRaw` (`NS.AuctionPrice:Pick`'s chosen price, human/copper), `value`/`valueRaw` (`NS.Util.RecordValue`: the higher of the picked auction price and vendor, human/copper), and `auctionSource` (`Pick`'s provenance tag, e.g. `"tsm:dbmarket"`, blank when unpriced); after `zone`, one **raw** `auc_<provider>_<key>` column is appended per `NS.Constants.AUCTION_KEYS` entry, exposing every price the addon actually captured regardless of which one `Pick` chose. `wowheadLink` (built from the item's bonus IDs) follows them, and the five ledger columns `dir`, `kind`, `holder`, `from`, `to` (timeline-ledger F4; legacy rows export the `NS.Util.RowDir`/`RowKind`/`RowHolder` defaults) are appended last so every earlier column keeps its index. `itemLink`, `sourceDetail`, `mapID`, `subzone` and `confidence` are intentionally omitted.
- **Insights tab** — exports the **analytics summary**. Providers compute a `Database:Stats` result over All Data (`Stats({})`) or Current View (`Stats(B:CurrentFilter())`, honoring the shared filter). Serializer: `Export:InsightsCSV` — a sectioned `Section,Label,Count,Value` CSV mirroring the Insights view (summary cards, then each breakdown: by source/quality/type/bound/character/weekday/hour/keystone/confidence, the currency sections, the top zones/items lists, and per-day activity).

Export is called directly by the Browser and registers no bus message; its copy window (Ctrl+C to copy) is deliberately separate from the debug copy window so their layouts can diverge.

### Search autocomplete (P9)

The Search box wears **`LibKa0s-Widgets-1.0`'s `Autocomplete`** (v1.70.0), leased through `core/WidgetsSetup.lua`'s `NS.MakeAutocomplete` and attached once in `B:BuildFilterBar`, after the box's own scripts, because the library **hooks** them (the box's filter, Enter and Escape run first and keep running). The list hangs directly under the box, anchored to both its bottom corners with a 1 px overlap, in the box's own gray border, so the two outlines read as one; it is parented to the box, so it follows every filter-bar relayout (FB-1) and the window's scale with no handler of its own. Typing is debounced (0.15 s); at most eight rows, each name in its quality color. Down / Up move the highlight, Enter picks it, Tab picks the highlighted or first row, and Esc closes the list and keeps the typed text. The list registers no event and arms no `OnUpdate`.

The list is one widget for every tab; **what it offers and what a pick does belong to the active tab**. `B:Suggest(text)` routes to the active spec's `suggest(text)` and `B:PickSuggestion(item)` to its `pick(item)`; a tab with no `suggest`, or whose Search is grayed, offers nothing. Switching tabs (`ApplyTabFilters`) and `B:Disable` close an open list.

| Tab | Offers | A pick |
|---|---|---|
| History, Insights | `B.SuggestNames`: the distinct item and currency names among the rows the shared filter shows with the typed text set aside, from the active dataset (the sample in test mode); gold rows are left out | `B.PickName`: Search reads exactly the name, and the filter applies |
| Holdings | `HT.Suggest`: the names `Holdings:Search` answers under this tab's filters, Gold included | `B.PickName` |
| Timeline | `TL.Suggest`: things held now plus anything the rollup has a day for, Gold first (`TM.Suggest`) | `TL:Pick`: charts the thing and leaves its name in Search |

History, Insights and Holdings rank names that **start** with the typed text first, then alphabetically (`B._rankSuggestions`). `B:SetSearchText(text)` is the one way a pick writes Search: the client fires the box's `OnTextChanged` from `SetText`, and when it does not (the headless kit, or no box on a degraded install) the filter is applied there instead, so it applies exactly once. With no library `NS.MakeAutocomplete` answers nil and the box stays a plain filter box. In-game check: [AC-1](smoke-tests.md).

### Footer

The footer is **shared window chrome** (issue #13), created on the frame by `EnsureFrame` and shown on both tabs. `B:UpdateFooter` prints `"Showing X of Y"` at the bottom-left, where X is `BrowserTable.matchCount` (records that passed the filter, captured before grouping) and Y is `#dataset()` — the current dataset, so both numbers track test mode and reflect the same shared filter regardless of tab.

`B:UpdateDbSize` (`Browser.lua:512`) prints the estimated stored size — `"Database ≈ <size>"` — right-aligned at the footer's bottom-right, from `Database:StorageStats().bytes` (the same estimate the settings panel shows) through `Util.FormatBytes`. It reflects the **real** persisted history (not the test dataset) and is recomputed only where storage can change or the view (re)opens — `SelectTab("History")`, `OnHistoryChanged`, and `OnDatasetChanged` — **never** on a filter keystroke (filtering can't change what's stored), so the per-keystroke path stays allocation-light.

### The launcher lives elsewhere now

The LDB launcher and its minimap button were `B:SetupMinimap` / `B:RefreshMinimap` / `B:SetMinimapHidden` in this file. They are **`core/LauncherSetup.lua`** now, on `LibKa0s-Launcher-1.0` (launcher-§1), and nothing about the button is this module's any more — including the icon, which used to be the Blizzard `INV_Misc_Bag_08` and is the addon's own logo today (launcher-§4). What the Browser still supplies is the one thing that is genuinely its own: **`B:Toggle`**, which `/lh toggle` calls — and so does the launcher's right-click menu's **Show window** entry, through that verb (launcher-§2, Launcher minor 4, LibKa0s v1.58.0). The launcher's left click opens the settings panel, not this window. See [ARCHITECTURE.md](ARCHITECTURE.md) for the object and its owner, and [settings-panel.md](settings-panel.md) for the **Minimap button** row.

The Browser subscribes to the bus on its **own** `NS.NewBusTarget()` (`B.__ev`, `Browser.lua:1273`) — never the shared bus-as-self — so its `SettingsChanged` / `HistoryChanged` / `RecordAdded` handlers don't clobber the Collector's or Analytics' handlers for the same messages (see [message-bus.md](message-bus.md)). `OnHistoryChanged` only does work when the window is open on the History tab.

## History tab — the virtualized table

`BrowserTable` is a **virtualized, object-pooled** table over `Database:Query`. The pipeline is **filter → group → sort → slice → bind** (`BrowserTable.lua:6`). Only the visible slice of rows ever exists as frames — there is never one frame per record.

### Column model

`BrowserTable.COLUMNS` (`BrowserTable.lua:163`) is a flat, ordered array; each entry carries a `key`, `label`, fixed `width` (or `flex = true` for the Item column, which absorbs the slack), `align`, a `desc` (header tooltip), a `valueFn(r)` (pure cell text) and a `sortFn(r)` (sort key). The columns are: Date, Time, Direction, iLvl, Bound (icon), Item (flex), Qty, Quality, Type, SubType, Source, Zone, Vendor Price, Auction Price, Character. **Date (66) and Time (40) match BankLedger's widths for the same two columns** — same date format, same font, so the two windows keep one rhythm; Time's earlier 32 predated its sort arrow and made the header wrap to two lines. The Bound lock is drawn at 11px (`LOCK_SIZE`) in the header and in every row — one mark, one size. **Character is intentionally last** — the order note (`BrowserTable.lua:160-162`) says any new column (Pawn, …) must be inserted before Character; the AH-price feature added the **Auction Price** column (its cell = `NS.AuctionPrice:Pick`'s chosen price for the row) right before it. Cell text is unit-tested by driving `valueFn` off this same `COLUMNS` model, so the tests exercise exactly the path the UI binds.

**Direction column and signed Qty (timeline-ledger spec §7).** The **Direction** column (86 px, left-aligned, BankLedger's Direction column in shape) shows a glyph and a label per row: `▲ Gain`, `▼ Loss`, `⇄ Transfer` (`Constants.DirGlyph` / `Constants.DirLabel`), glyph and label both tinted from `Constants.DirRGB` (green, red, gray) through `LedgerFormat.Color`; a legacy row with no `dir` reads as Gain (`NS.Util.RowDir`). The default font has none of those glyphs and would draw boxes, so the glyph is its **own FontString** on the row (`row.dirGlyph`, built in `BuildRow`) set in the mono face (`C.FONT_MONO`, LibKa0s's JetBrains Mono; that it carries U+25B2, U+25BC and U+21C4 is smoke LED-P2-17), placed in the cell's first 12+2 px, while the label stays in the row font. `BrowserTable:PaintCell` is the one painter: the Direction column sets the glyph's text, color **and** shown state on every bind (rows are pooled), any other column handed the glyph hides it, and a group-header bind hides it. Sorting and grouping by Direction are unchanged (gains, losses, transfers). **Qty is signed:** `+3` for a gain, `-3` for a loss, a bare number for a transfer (`LedgerFormat.QtyText`; ASCII `-` because the font has no U+2212). `quantity` itself stays unsigned in storage. A gold row shows its signed amount as money in the Qty column, in the pale gold `Constants.GOLD_RGB`, and its Item cell says `Gold`. **Qty is measured, not fixed** (P5 owner feedback: a fixed 34 px cut gold to `9661…`): 34 px is the floor (a count), and `BrowserTable:MeasureColumns(frame)` widens it at the row font (`GameFontHighlightSmall`, `GetUnboundedStringWidth`) to the widest signed gold string the cell can show, the gold cap `9,999,999g 99s 99c` with either sign, rendered through the Qty column's own `valueFn`, plus 2 px. `Browser` calls it right before it takes the final window floor, so `MinFrameWidth` (and so `B:MinWidth`) carries the measured width; a headless font measures 0 and keeps the floor.

**Default view.** A view that never stored a Direction (the stock view and every view saved before the ledger) opens on **Gains + Losses**; transfers join it when `settings.showTransfers` is on (`defaultDirSet`), applied on Clear or reopen. The same default view also applies the **minimum-quality floor** (`applyQualityFloor`): items below `settings.qualityThreshold` are hidden until the Quality filter picks qualities explicitly, and whitelisted ids are exempt. Both are *view* filters; nothing below the floor is missing from the ledger. A stored empty Direction set means All.

**Group by Direction and Holder.** `GROUP_OPTIONS` gains `dir` and `holder` after Character, so a History view can be split into gains, losses and transfers, or by whose holdings the row belongs to (`§warband` reads Warband).

**Group by Type & SubType** (timeline-ledger P9). `GROUP_OPTIONS` gains `typesub` ("Group: Type & SubType") right after Type, and the Holdings tab offers it too (see [Holdings tab](#holdings-tab)). One group per type/subtype pair, built by the shared `NS.LedgerFormat.TypeSub(itemType, itemSubType)`: the raw key is `<Type>\001<SubType>` and the header reads `Type: <Type> · <SubType>`, or just `Type: <Type>` when the subtype is missing or blank (no trailing separator). A currency row carries `itemType = "Currency"` and its token-list category as the subtype, so it reads `Type: Currency · <category>`; a row with no type reads `Type: Unknown`. The mode has no column of its own, so groups order by the lowercased raw key (type, then subtype, alphabetical; `\001` sorts a bare type ahead of its subtyped siblings), `groupAsc` still flips the direction, and a header click sorts rows as usual. A saved view stores it like any other `groupBy`.

The **Bound column** renders no text — it draws a tinted padlock (`BOUND_STYLE`, `BrowserTable.lua:39`): gray = unbound, off-white = BoE, green = BoP, orange = account-bound, blue = warbound. The lock atlas is resolved once against a fallback list (`LOCK_ATLASES`, `BrowserTable.lua:54`) so it never renders blank on clients missing a given atlas; the header lock is drawn in the header gold every other column label wears, and its tooltip shows the full legend (`AddBoundLegend`) — one tinted lock per state, built through `NS.IconMarkup`'s color form. It used to call `CreateTextureMarkup(path, 64, 64, 14, 14, 0, 1, 0, 1, r, g, b)`, whose last two arguments are `xOffset`/`yOffset` rather than color: the locks drew white and scattered up to 255px off their lines. The **Character column** names the row's holder (`NS.LedgerFormat.HolderLabel`, so the Warband half of a move reads **Warband**; it sorts and groups by the same label), and it and the **Item/Quality columns** are colorized — the holder's class color (`BrowserTable:HolderClassFile`: the row's own class when the row sits on its writer, the stored class of another character, none for the Warband) and item-quality color respectively (`BindRow`, `BrowserTable.lua:1107`).

### Filter → group → sort → slice → bind

`BuildDisplayList` (`BrowserTable.lua:731`) runs the pipeline: `Database:QueryList(CurrentRecords(), filter)` filters, `matchCount` is captured, then `SortRecords` and `GroupRecords` produce the flat display list. `CurrentRecords` (`BrowserTable.lua:724`) is just `Database:ActiveHistory()`, so the table shows synthetic data in test mode and live history otherwise.

- **Sort** — `SortRecords` (`BrowserTable.lua:611`) does a **stable** sort into a *new* array (records are never mutated); because Lua 5.1's `table.sort` isn't stable it decorates each record with its original index and tiebreaks on it, preserving chronological order among equal keys. `SetSort` (`BrowserTable.lua:634`) handles header clicks: re-clicking the active column flips direction, a new numeric column starts descending and a text column ascending (`NUMERIC_SORT`, `BrowserTable.lua:246`). Arrows are inline texture markup (`ARROW_ASC`/`ARROW_DESC`) because the default font has no ▲/▼ glyphs, and they are **tinted to the header gold** — an inline texture is not reached by the FontString's `SetTextColor`, so an untinted arrow reads white beside a gold label. The group-header disclosure chevron is tinted the same way, for the same reason.
- **Group** — `GroupRecords` (`BrowserTable.lua:672`) partitions the sorted records under collapsible `{ kind="header" }` entries when `groupBy ≠ "none"`. The modes are None / Day / Quality / Type / Type & SubType / Source / Zone / Character / Direction / Holder (`GROUP_OPTIONS` in `modules/BrowserFilterBar.lua`, ordered to mirror the columns). `groupOf` (`BrowserTable.lua:304`) namespaces each group key by its mode (`groupBy .. "\001" .. raw`) so a zone named "Kill" can't collide with the Kill source in the collapsed-state map. Groups sort by the grouping column's natural order (direction `groupAsc`), and the row sort still holds within each group. **Clicking the grouped column's header flips the group order** rather than the row sort (`SetSort`, `BrowserTable.lua:634`); `UpdateHeaderArrows` shows the group-order arrow on the grouped column and the sort arrow on the sort column. Collapsing a group (`ToggleCollapse`, `BrowserTable.lua:661`) emits only its header.
- **Slice + bind** — `Bind` (`BrowserTable.lua:1065`) drives a `FauxScrollFrameTemplate`: it computes `numVisible` from the viewport height, calls `FauxScrollFrame_Update`, reads the scroll offset, releases all rows, then acquires and binds only `list[offset+1 .. offset+numVisible]`. Empty state shows either "No records match your filters." or "No loot recorded yet. Go kill something." depending on whether a filter is active.

### Object pooling

`AcquireRow` (`BrowserTable.lua:760`) pops a free row from `rowPool` or builds a new pooled `Button` (one FontString per column + a stripe, highlight, bound-lock texture and group-header FontString). `ReleaseAllRows` (`BrowserTable.lua:899`) hides every active row and returns it to the free list before each bind — so the frame count is bounded by the viewport, never by history size (Standard standalone-windows). Column geometry is recomputed by `LayoutRowCells` (`BrowserTable.lua:874`) and `BuildHeaderCells` (`BrowserTable.lua:1003`) — the flex Item column takes `total − fixed`, and `Bind` re-lays the header on every pass so header and rows stay aligned across resizes.

### Row actions

Each pooled row wires three interactions (`AcquireRow`, `BrowserTable.lua:807-849`):

- **Hover** → the full in-game item tooltip via `GameTooltip:SetHyperlink(record.itemLink)`; INFERRED rows get a "Source inferred (uncertain)." note, plus a hint line advertising the click actions. A **gold row** has no link, so it gets BankLedger's gold tooltip instead (`Compat.ShowAmountTooltip`, presence-gated): a `Gold` title in `Constants.GOLD_RGB`, an `Amount` double line with the signed coin string (`LedgerFormat.QtyText`, the Qty cell's own text), and a gray `Right-click for options` hint. Leaving the row hides the tooltip (`Compat.HideTooltip`).
- **Shift-left-click** → `ChatEdit_InsertLink(link)` links the item to chat.
- **Right-click** → `ShowRowMenu` (`BrowserTable.lua`), a tiny flat-skin popup (gold border so it reads against the 3D world) with **Link to chat**, **Blacklist item**, and **Delete**. **Blacklist item** (issue #14) calls `NS.Filters:AddBlacklist(record.itemID)` — point-in-time, so the clicked row (and every other stored row of that id) stays in the browser; only *future* loots of the id are dropped. Use **Delete** to remove existing rows. There is deliberately no whitelist action here (whitelisting is about items that were *not* recorded, so there's no row to act on). **Delete** calls `NS.Database:Delete(pred)` (which fires `HistoryChanged`) and repaints immediately.

A group header's left-click toggles its collapse instead.

The right-click menu also carries **Show in Timeline**; see [Row actions: Show in Timeline, Forget this character](#row-actions-show-in-timeline-forget-this-character).

## Insights tab — Analytics

`Analytics:Attach` (`Analytics.lua`) builds a `UIPanelScrollFrameTemplate` filling the pane, a row of stat/highlight cards, and a stack of breakdown sections. Everything is **driven off a single `Database:Stats(filter)` pass** (`Analytics:Refresh`) — one O(n) aggregation whose result struct feeds every card, bar, strip and list.

### Scope — the shared filter (issue #13)

Insights has **no range selector of its own**. `Analytics:Refresh` scopes every stat by the browser's shared filter — `Database:Stats(NS.Browser:CurrentFilter())` — so the Insights view and the History table always reflect the exact same criteria (the shared Date dropdown, plus every column filter). An empty filter aggregates the whole visible history. Analytics live-refreshes while it's the visible tab (its own `RecordAdded`/`HistoryChanged` bus subscription) and whenever the shared filter changes on the Insights tab (`ApplyFilter`).

### Stat & highlight cards

`CARD_DEFS` (`Analytics.lua:23`) — 4 columns per row, `wide` cards spanning 2: records, distinct items, characters, value, active days, epic+ drops, best drop (ilvl), richest drop, date range (wide), busiest day (wide). `UpdateCards` (`Analytics.lua:120`) reads them straight from `stats.totals`; string cards (value, richest, span, busy) use a smaller font. "Value" throughout Insights is the **derived** per-record worth (`Util.RecordValue` — auction price snapshot if captured, else vendor sell price) `× quantity`, never the raw vendor price alone. See [schema.md](schema.md).

### Ledger cards and the Gains and losses section

When any row in range is a loss or a transfer (`AnalyticsLedger.HasLedger`), Insights adds **Gained**, **Lost**, **Net** and **Transfers** cards (green `+`, red `-`, a gray dash for exactly zero; `Database:Stats(...).ledger`) and, below the LOOT block, a **Gains and losses** divider with three back-to-back charts: *by reason*, *by character* and *by kind*. Losses grow left of a fixed center axis in red and gains right in green, on one shared scale per chart, so the two sides compare honestly. A gains-only history (every pre-ledger account) renders exactly as before, and the existing LOOT and CURRENCY charts count gains only (`dir == IN`). A move between two holders (Phase 7) is a loss on the sender and a gain on the receiver, and both count like any other: each appears under its own reason (**Warband Deposit**, **Warband Withdraw**, **Alt Mail**, **Alt Trade**, **Currency Transfer**, each with its own chart color), the *by character* chart keys on the row's holder (`AnalyticsLedger.HolderShort`, so the Warband carries its own half as **Warband**), and over the whole account the two halves net to zero.

**Caveat.** When the player kept their history at the upgrade prompt (`resetPrompt == "kept"`) and the range holds rows older than `ledgerSince`, a yellow line says: before that date only gains were recorded, so totals for the period overstate net.

**The Direction filter applies to Insights too.** Insights reads the shared filter, so under the default view (Gains + Losses) the **Transfers** card reads 0. That is expected, not a bug: tick Transfers in the Direction dropdown to count them.

### Breakdown sections

`LayoutCharts` (`Analytics.lua:621`) binds and positions each section top-down off `self.stats` through one file-local helper per section (`layoutCharacters` … `layoutRankedLists`, then `layoutCurrency`), returning the running y-cursor (empty sections are skipped entirely). The sections sit under two full-width dividers (`sectionDivider`, `AnalyticsCharts.lua:187`) — a centered gold title flanked by rule lines — that split the pane into **LOOT** and **CURRENCY**:

**LOOT** — every item-centric chart, plus the Top zones/items panels (moved under this divider so the whole item side of Insights is one block). The source/character/value charts here are **items-only** — currency is excluded so per-character totals tally with the item-attribute charts (currency lives entirely in the CURRENCY section). The headline **records** KPI still counts everything.

Section titles are Title Case; charts render top-down in this order:

| Section | Source field | Renderer |
|---|---|---|
| Loot By Character | `byChar` (items only, count > 0) | class-colored horizontal bars (first chart) |
| Loot By Source | `bySource` (items only) | horizontal bars, per-source color + legend |
| Loot By Character × Source | `charBySource` (items only) | stacked bars (Y = character, segments colored like Loot By Source, order = parent's) + legend |
| Value By Source | `valueBySource` (items only) | horizontal bars, per-source color, order by value desc + legend |
| Value By Character × Source | `charValueBySource` (items only) | stacked bars (segment magnitude = vendor value, order = parent's value-desc) + legend |
| Loot By Quality | `byQuality` (quality order) | horizontal bars, quality color + legend |
| Loot By Character × Quality | `charByQuality` | stacked bars (segments quality-colored) + legend |
| Loot By Item Type | `byType` | horizontal bars, standard-palette color per type (rank = count order) + legend |
| Loot By Character × Item Type | `charByType` | stacked bars (same per-type palette colors) + legend |
| Loot By Bound Type | `byBound` (`BOUND_ORDER`, sorted count desc) | horizontal bars, bound color + legend |
| Loot By Character × Bound Type | `charByBound` | stacked bars (segments bound-colored, order = parent's count-desc) + legend |
| Loot Over Time (Per Day) | `byDay` | vertical strip |
| Value Over Time (Per Day) | `valueByDay` | vertical strip |
| Loot By Hour Of Day | `byHour` (24 buckets) | vertical strip |
| Loot By Weekday | `byWeekday` (Sun–Sat) | horizontal bars, one palette color per day |
| Top Zones / Top Items By Count / Top Items By Value | `topZones` / `topItems` / `topItemsByValue` | ranked list panels |

Each "… × Character" companion (`renderCharCompanion`) is placed immediately below its parent: the character is on the Y axis (short name, class-colored label) and the X axis is one stacked bar segmented by that parent chart's categories, in the **same order as the parent's Y axis** and reusing its segment colors. A character spanning more than 9 categories keeps its top 8 and lumps the rest into a neutral **Other** segment (`Analytics._charStackSegments`).

Every categorical bar chart (single-bar and companion) draws a **color-swatch legend** below it, aligned to the bars' left edge (not the text labels). On single-bar charts the label text is colored to match its bar (`renderBarSection` defaults `labelColor` to the bar color) unless the caller sets an explicit color (quality already colors its own labels; per-character bars stay class-colored). `byKeystone` (Mythic+ by keystone level) and `byConfidence` (attribution confidence) are still computed and feed the **Export**, but their in-dashboard charts (and per-character companions) were removed; the old **Quality mix** stacked bar was also removed.

**CURRENCY** — only shown when the filtered range has at least one currency event (`stats.currencyTotals.events > 0`), introduced by the gold **CURRENCY** divider (the old "Currency — N types — biggest: …" summary line was removed):

| Section | Source field | Renderer |
|---|---|---|
| Currency Collected | `byCurrency` (qty per currency) | horizontal bars, standard-palette color per currency (rank = qty order) + legend |
| Currency By Type × Source | `byCurrency` + `currencySourceMatrix` (qty per currency, segmented by source) | stacked horizontal bars + a source-color legend (`renderLegend`) below |
| Currency By Character × Type | `currencyCharMatrix` (qty per character → currency) | stacked bars (Y = character, one segment per currency, same palette colors as Currency Collected) + a per-currency legend below |
| Currency Over Time (Per Day) | `currencyByDay` | vertical strip |

> `currencyBySource` (source → total qty across all currencies) is still computed and feeds the **Export** "Currency by Source" section, but no longer has an in-dashboard chart.

These pooled renderers back the sections:

- **`renderBarSection`** (`AnalyticsCharts.lua:235`) — a header + one horizontal bar per row (fixed label + track/fill + value). It normalizes so the largest bar fills the track and the rest scale relative to it.
- **`renderStackedBarSection`** (`AnalyticsCharts.lua:271`) — like `renderBarSection`, but each row is one stacked bar whose segments are pre-computed fractions of a shared max. Backs **Currency by Type × Source**, **Currency by Character × Type**, and all five **… by Character** loot companions. Honors an optional `row.labelColor` (class-colors the character-row labels). Each segment is a mouse-enabled frame carrying a `tip` (`"<category>: <value>"`) shown on hover.
- **`renderLegend`** (`AnalyticsCharts.lua:293`) — a wrapped row of color-swatch + label chips, drawn below **every** categorical bar chart (single-bar and stacked). Chips start at the bars' left edge (`pad + LABELW + 6`), not the text-label column. Long chip labels are truncated to `LEGEND_MAXCHARS` with an ellipsis; hovering a chip shows the full label. `renderBarSection` takes an optional `legendPool` to draw one from its own rows.
- **`renderCharCompanion`** (`AnalyticsCharts.lua:315`) — wraps `_buildCharStackRows` + `renderStackedBarSection` + `renderLegend` for the five loot companions (color + label + value formatter per chart).

Labels on bar/stacked-bar rows are capped to `LABEL_MAXCHARS` glyphs with an ellipsis (`Analytics._truncate`) and carry a hover tooltip with the full name; the label column was widened (`LABELW`) to reduce truncation. **Every Insights hover tooltip states the value as well as the name** — `"<full label>:  <value>"`, built by `Analytics._tipText` — because the on-chart value text is clipped to a fixed column and the label itself is ellipsised, so the tooltip is the only place the exact figure is readable. It applies to bar rows, stacked-bar rows (the row's total), ranked-list rows (count or money), the legend chips of a bar section, and the already-valued strip bars and stacked segments; the one exception is a legend chip built from a category order (the "… by Character" companions), which has no single value — `_tipText` then falls back to the label alone. All of them are pinned just above-and-right of the cursor (`showCursorTooltip`), not the row's far-right edge. Categories with **no predefined palette** (item types, currencies, weekdays — everything except class / bound / quality / source) are colored from a shared standard palette (`Analytics.paletteColor`, built into a per-chart `{key → color}` map by `paletteMap`): the sequence is inverse-VIBGYOR (R→O→Y→G→B→I→V) plus a lighter and a darker band (21 colors), assigned by a category's **rank in its chart's sort order** so consecutive bars/segments are always drawn from adjacent, dissimilar hues. Money strings in Insights use ~25%-smaller coin glyphs (`FormatMoney(copper, COIN_H)`).
- **`renderStrip`** (`AnalyticsCharts.lua:328`) — a per-bucket vertical strip with an axis line and rotated x-axis labels (thinned out when bars get narrow); each bar's hover shows the bucket's info line. The per-day strips share a `firstTs..lastTs` day-key list (gaps included) from `dayKeyList`, capped to the most recent `MAX_DAY_BARS = 60`.
- **`renderListPanel`** (`AnalyticsCharts.lua:377`) — a ranked list panel capped at 10 rows; item rows are quality-colored with a gold star before epic+ items (`starMarkup`, `AnalyticsFormat.lua:73`, resolved against a fallback atlas list). The two item lists share the same entry tables from `stats.byItem` — two orderings, count-desc and value-desc.

Every renderer draws from a per-section pool in `self.pool` (`Analytics.lua:212`); `LayoutCharts` releases all pools up front, then re-acquires only the widgets it needs, so no chart holds a widget per data point. `Analytics:Layout` (`Analytics.lua:140`) sets the scroll child height from the final y-cursor. If the range has no records, `HideAllCharts` runs and an empty-state label shows (both dividers hide with it).

Analytics subscribes to `RecordAdded` / `HistoryChanged` on its own `NS.NewBusTarget()` (`Analytics.lua:259`) and live-refreshes only while the Insights tab is visible.

### Widget pools are recycled, and that is tested

Every bar, stacked bar, swatch, strip segment and list row comes out of one of the 35 pools in
`self.pool`, and `LayoutCharts` releases every one of them at the top of each layout pass
(`NS.Pool.ReleaseAll`, `Analytics.lua:624`). That only costs nothing if released widgets come back.
Until 2026-08-24 `releaseAll` hid each active object and dropped it, so `pool.free` was empty on
every acquire and the factory ran each time: a fresh frame per chart element on every re-render,
and frames are never destroyed in WoW, so a session's filter changes and tab switches piled up
hidden frames for good.

The guarantee is the test, not the fix: `tests/test_analytics.lua` counts factory calls across two
passes through `NS.Pool` and requires the second to build nothing. Reading `pool.free` alone would
pass against a pool nobody reuses. The one allocation on the loot path that is deliberately left
unmeasured is recorded in [combat-path-sweep.md](combat-path-sweep.md#the-allocation-that-is-not-measured-and-stays-that-way).

## Holdings tab

`modules/HoldingsTab.lua` registers the third tab (`{ name = "Holdings", order = 40 }`) through `B:RegisterTab` (timeline-ledger spec §8.2). It lists what the account **holds right now**, from `NS.Holdings:Search` over `db.global.holdings`: one line per thing (item, currency, or gold) with its account total and value; clicking a line expands it into one indented line per holder — the character's name class-colored (`§warband` reads "Warband"), the container split (`Bags 12 · Bank 40 · Warband 100`, fixed order bags, equipped, bank, mail, AH, warband tabs) and the age of the oldest scan feeding that count, grayed once it is a day old.

`HoldingsTab.BuildModel(filter, expanded, sortKey, sortAsc, groupBy, collapsed)` is pure and carries every decision; the view is a scroll frame of fixed-height rows from one `NS.Pool` pool, released and re-acquired on each `Refresh`, so a repaint reuses its frames.

**Columns** (`HoldingsTab.COLUMNS`): Name · iLvl · Quality · Type · SubType · AH Price · Total · Value. Name flexes; the rest take History's widths for the same columns. When the pane is too narrow for Name to keep 160 px, the optional columns drop right to left (AH Price, then SubType, Type, Quality, iLvl); Name, Total and Value always stay (`HoldingsTab.ColumnLayout(width)`). iLvl is gear only (`Compat.GearItemLevel`); Quality is the quality label in its color; Type / SubType are the item's (`Currency` and its category for a currency, `Gold` and blank for gold); AH Price is the picked unit price, as History's Auction Price column (`NS.AuctionPrice:Pick` over `GatherAll`), blank when there is none. Every header cell sorts its column and a second click flips it (numeric columns start descending, text ascending), with History's gold sort arrow. The header is its own frame holding exactly one cell per column. **Banding** follows History's stripe (3% white on every second band): one band per thing, and an expanded thing's holder lines share its band. **Hover** on a thing line shows its tooltip: the item's own (its stored link, else `item:<id>`), the currency's, or a plain Gold title with the formatted amount (`Compat.ShowItemTooltip` / `ShowCurrencyTooltip` / `ShowTextTooltip`, each presence-gated). A holder line's container split spans the visible metadata columns. Value is gold's own copper, `0` for a currency, and for an item `NS.Util.RecordValue` over the live picked auction price and the vendor sell price (`Compat.GetItemSellPrice`) times the count. The tab repaints on `HoldingsChanged` while on screen (its own `NS.NewBusTarget()`, `HoldingsTab.__ev`, dropped by `NS.StandDown`); the Reconciler only sends that from its out-of-combat flush.

**Filters.** It reads the shared filter like the other tabs, but only the fields `Holdings:Search` understands: search text, Quality, Type, SubType and Character (which narrows the holders, and so the totals). Date, Source, Bound and Zone describe a loot event, not something held: they are **grayed** on this tab (see [per-tab filter graying](#per-tab-filter-graying-spec-80)), and its Character list shows holders (with **Warband**), not loot characters. The Character dropdown is one control with two option sources, so switching between a holders tab and History / Insights drops any pick the new list does not offer (`B:PruneCharSet`, through `SetCharSet`; the logged-in character is always kept): a Warband pick carried to a History with no Warband rows would otherwise filter every row out under a raw-key label (History lists **Warband** itself once a holder move puts a row on it). The window opens scoped to the logged-in character, so the tab first shows that character's holdings; widen the Character filter for the account.

**Grouping** (timeline-ledger P6). The shared Group dropdown is live on this tab, over its own modes: **None, Quality, Type, SubType, Type & SubType, Character** (`HoldingsTab.GROUPS`, the spec's `groups`; `Group: SubType` is a Holdings-only entry, so History's menu is unchanged; Type & SubType is History's P9 mode, same labels and order). Holdings keeps a **per-tab group value**, `HoldingsTab.groupBy`, rather than reading History's: `B:SetGroup` routes the dropdown's pick to the active tab's `setGroup`, and `B:SyncGroupControl` (on every tab switch and after `ApplyView`) repaints the dropdown's option set and value for the active tab, so a pick on Holdings never moves `BrowserTable.groupBy` and History's pick comes back on History. Any other mode handed to `HoldingsTab:SetGroupBy` or `BuildModel` (Day, Source, Zone, Direction, Holder) reads as None (`HoldingsTab.GroupMode`). The Holdings group is session state: it is not part of the saved view, and Save / Reset / Clear do not touch it. Headers are History's: a gold chevron (right when collapsed, down when open), `<Prefix>: <Value>` and a gray `(N)`, N being the things in the group; a left click collapses or opens the group, and the collapse state (`HoldingsTab.collapsed`, keys namespaced by mode like History's) lasts the session. Groups order as History's read: Quality by rank, highest first, with no quality (gold) last as `—`; Type and SubType alphabetically (`Unknown` for none); Type & SubType by type then subtype, as History's (gold reads `Type: Gold`, a currency `Type: Currency · <category>`); Character alphabetically with the Warband last. Under **Character** a thing is listed under every holder that has it, with that holder's count as its Total and its Value scaled to that count, and expanding it lists only that holder's container split (its expand key names the holder, so its copies in other groups stay closed); every other mode keeps the all-holders total. The column sort holds within each group. **Banding runs down the whole list**: the stripe counts things across groups rather than restarting in each, a header row carries none, and a holder line keeps its thing's band.

## Timeline tab

`modules/Timeline.lua` registers the second tab (`{ name = "Timeline", order = 30, filters = { search, date, char }, charSource = "holders" }`) through `B:RegisterTab` (timeline-ledger spec §8.1). It charts **one thing at a time** (gold, one currency or one item) over the Date range, from the daily rollup (see [data-flow.md](data-flow.md#daily-rollup)). `modules/TimelineModel.lua` is pure and carries every decision; the view only paints what `TimelineModel.Build` returns.

- **Picker.** The thing is chosen with the browser's shared **Search** box, through its autocomplete (see [Search autocomplete](#search-autocomplete-p9)). This tab's `suggest` offers matching things (everything held now, plus anything the rollup has a day for, so an item nobody holds any more is still reachable), with **Gold** first when "gol" is typed. A pick charts the thing and leaves its name in Search. The pick is remembered in `savedView.timelineThing` (`B:SetViewField`, which materializes a copy of the stock view when none is stored; see [schema.md](schema.md#state-outside-the-rows)). The default is gold.
- **Lines.** A thick **Total** line plus up to `settings.timelineMaxLines` holders (default 8, 2 to 16), the richest by latest balance first. The **Character** filter narrows the field before the cap; its list on this tab is the holders (characters the ledger knows, plus **Warband**). Characters draw in class colors, the Warband in its own blue; a character that has not logged in since the upgrade has no stored class and draws gray until it does. **The window opens scoped to the logged-in character**, so the Timeline first shows Total plus that character; widen the Character filter for the account.
- **Axes.** Y is in the thing's native unit with nice ticks (gold in whole gold, labeled with a `g`; currencies and items as counts); X follows the Date filter, which now also offers **Last 90 days** and **Last year** (every tab, `NS.Util.RangeFrom("90d" / "1y")`). **Today** and **Last 7 days** draw intraday steps when the range sits inside the retention and the rebuild checks out; the longer ranges draw one point per day. The Total steps where its holders step (`TM.TotalSeries` emits the left-limit sum before the post-step sum), so it overlays them rather than cutting a diagonal across a step.
- **In/out strip.** Under the plot, one pair of bars per day for the drawn holders' summed gained (up, green) and lost (down, red) quantity, aligned to the plot's x axis. It is the Total's and does not change when lines are hidden — not even with every line hidden, when the chart is cleared and has no plot rect to ask: the strip then takes the same x mapping from the chart's published paddings (`NS.LineChartChrome()`) and the width `Layout` last rendered at. **Hovering a day's column** (its pooled bar frame spans the strip's full height, so the gain bar, the loss bar and the gap all count) shows `<day> · Total` with **Gained** `+N` (green), **Lost** `-N` (red) and **Net** signed and colored by its sign, gold as coin strings (`NS.Util.FormatMoney`, History's Qty formatter) and anything else as counts (`TM.FlowLines`, drawn by `Compat.ShowLinesTooltip` at the cursor). A zero side reads `0`; a day with no flow has no column, so no tooltip. Leaving the column hides it; a live repaint under it redraws it on the new numbers, or hides it if the day lost its flow. The chart's hover ending hides only a tooltip the chart owns, so moving from the plot onto the strip does not knock the strip's tooltip down.
- **Legend.** One entry per line, in that line's color, the Total first. Each entry is a button (tooltip "Click to hide/show") that toggles its line; a hidden entry keeps its place and dims to gray at 0.4 alpha. The chart draws only the visible lines and takes its y range over them (`TM.Visible`, `TM.YRange`, `TM.ChartData(m, hidden)`). With every line hidden the chart draws no axes and says "All lines hidden — click a legend entry to show it."; the legend stays.
- **Total only.** A toggle in the header, beside the thing's name, hides every holder line and keeps the Total; turning it off brings back exactly the lines shown before. It reads as on whenever the Total is drawn and every holder in the chart is hidden, however that came about, so legend clicks move it too. It is remembered in `savedView.timelineTotalOnly` (default off, `B:SetViewField`); the per-line hidden set (`TL.hidden`, keyed by holder) is session-only, outlives a change of thing or Date range, and ignores holders the current chart does not draw.
- **Hover.** A crosshair snaps to the nearest day; the tooltip lists each visible line's value that day and the Total's Gained / Lost. Leaving the plot, or hiding the window, hides both. A live repaint (a coalesced `HOLDINGS_CHANGED` / `RECORD_ADDED`) drops the hover first (`chart:ClearHover()` in `TL:Refresh`), because the chart re-fires its hover only when the nearest index changes; a cursor still on the plot re-hovers against the new data on the next frame.
- **Dashed.** A holder's line is dashed from its genesis until `meta.completeAt` (its bank, or the Warband's tabs, first read) and solid after. When the range reaches `ledgerSince`, a dashed vertical rule marks where capture began.
- **Without the library.** With `LibKa0s-Widgets-1.0` absent, `NS.MakeLineChart` answers nil and the pane says so (`NS.LIBKA0S_MISSING`) instead of drawing.

`TL:Enable` / `TL:Disable` own a private bus target (`TL.__ev`) for `HOLDINGS_CHANGED` and `RECORD_ADDED`, behind one coalesced repaint that runs only while the pane is visible; `NS.StandDown` calls `Disable`. See [disabled-state.md](disabled-state.md).

### Per-tab filter graying (spec §8.0)

The filter bar is one window-wide singleton, so a tab that does not use a control **grays it instead of hiding it**: the bar never reflows when you change tabs, and the filter it still holds stays visible. A grayed control is disabled (`SetEnabled(false)`, or `Disable` for the Search box) at alpha 0.4, so a click on it does nothing. A tab spec without a `filters` set honors everything.

| Tab | Honors | Grayed |
|---|---|---|
| History | every control | none |
| Insights | every control | none |
| Timeline | Search, Date, Character | Group, Bound, Quality, Type, SubType, Source, Zone, Export |
| Holdings | Search, Group, Quality, Type, SubType, Character | Date, Direction, Source, Bound, Zone, Export |

Character on the Timeline and Holdings lists holders rather than loot characters (`charSource = "holders"`), including **Warband**.

### Row actions: Show in Timeline, Forget this character

- **Show in Timeline** is on a History row's right-click menu and on a Holdings thing's. It sets the Timeline's thing (`B:ShowTimeline(key)`) and switches to the tab. `BrowserTable:RowMenuItems(record)` builds the History menu as data and `BrowserTable:ShowMenu(anchor, items)` is the shared popup, so the Holdings tab reuses it through `HoldingsTab.RowActions(line)`.
- **Forget this character** is on a Holdings **holder** line. It confirms through `KA0S_LOOTHISTORY_FORGET_HOLDER` (`settings/Slash.lua`, the holder key passed as the popup's data), then `Reconciler:ForgetHolder` drops that character's holdings and rollup cells. History rows stay. It is grayed on the logged-in character (its next scan would put it straight back) and on the Warband.

## Menus: two mechanisms, on purpose

This addon draws **two** kinds of menu and neither is a Blizzard `UIDropDownMenu` — both avoid that
API's protected-call taint surface, and neither is going to replace the other.

**The flat dropdown is `LibKa0s-Widgets-1.0`'s**, reached through `core/WidgetsSetup.lua`'s
`NS.MakeDropdown`. Ten instances: the filter bar's Group-by, Date, Bound, Quality, Type, SubType,
Source, Zone and Character, plus the export modal's Data Set picker. Its popup is a **process-wide
singleton** shared with every other Ka0s addon that has adopted the major — one menu open at a time
across the whole client, parented to `UIParent` at `FULLSCREEN_DIALOG`, outliving any window that
dropped it. Two consequences this addon has to honor: every frame that owns a dropdown sits *below*
that strata (the History window is `HIGH`, the export modal is `DIALOG`) so the menu draws above
whatever dropped it, and every **non-click close path** calls `NS.CloseMenu()` — the window's
`OnHide` (which is also the Escape / `UISpecialFrames` route), `Browser:Hide` (the slash-command
close) and the export modal's `OnHide`. A frame's own `Hide()` cannot reach a popup it does not own.

The popup does **not** intercept the click that dismisses it. Since LibKa0s v1.13.0 (Widgets minor 5)
it registers `GLOBAL_MOUSE_DOWN` while shown and hides on a press that is neither over itself nor
over the dropdown that dropped it, so one press both closes the menu and reaches whatever is under
the cursor (`libs/LibKa0s/Widgets.lua`). Through minor 4 it was a full-screen `Button` at
`FULLSCREEN` whose lack of `RegisterForClicks` took `LeftButtonUp` and nothing else — and this addon
is where that was found, because a right-click on a history row with a filter menu open simply did
nothing.

**`BrowserTable:ShowRowMenu` stays hand-rolled**, and coexists. It is a right-click **action list**,
not a labeled selector: it shows no current value and picking an item performs an action (link to
chat, blacklist, delete) rather than changing a setting. It also needs **per-row disable** —
"Link to chat" is dead without an `itemLink`, "Blacklist item" without an `itemID` — and per-row
disable is a *documented, deliberate absence* from the major: `opt.isActive` reports a state, it
does not gate a click. Converting it would mean either losing the disable or growing the library a
feature no consumer has asked for. It keeps its own small popup and its own catcher.

## Test mode (`/lh test`) — synthetic preview

The History window's test mode (preview-mode, options-ui-§15). `BrowserTable:SetTestMode` (`BrowserTable.lua:567`) is the one switch, and three things drive it: the Master controls **Test mode** checkbox (`state.testMode`, a session-only row), `/lh test` (`ToggleTestMode`, `BrowserTable.lua:596`) and the combat start (`EndTestModeForCombat`, `BrowserTable.lua:602`, called from the Browser's `PLAYER_REGEN_DISABLED` handler). A start publishes a synthetic dataset to `NS.State.testRecords` and opens the window; a stop never opens it. A start is refused with one chat line, leaving the box unticked, when the General visibility setting keeps the window hidden or the player is in combat. Every start, stop and refusal refreshes the settings panel so the box follows it. Because `Database:ActiveHistory` (`Database.lua:402`) returns `NS.State.testRecords` when present, the fake data flows through the *same* read paths (`Query` / `Stats` / `CurrentRecords`) — so it drives **both** the History table and the Insights charts at once, while write paths (Add / prune) always target the real history and never see the override. `OnDatasetChanged` (`Browser.lua:534`) rebuilds the filter dropdowns from the new dataset, resets to the stock view + all players in test mode (test characters differ from the current one), and toggles the red "TEST MODE" badge beside the title.

`BuildTestData` (`BrowserTable.lua:464`) generates a deliberately **non-uniform** spread — weighted-random sources / qualities / classes / zones / types / timestamps, a handful of "hot" items over a long tail, keystone and evening-hour peaks — so the charts read like real play. It uses a deterministic Park–Miller LCG with a fixed seed (`testRng`, `BrowserTable.lua:399`), **not** `math.random`, so the dataset is byte-identical every run and the headless tests stay stable. A coverage seed pass first guarantees every source / quality / class / binding appears and the range spans more than 14 days regardless of the dice.

The same switch fills the **Holdings** and **Timeline** tabs (timeline-ledger P6). Beside `testRecords`, `NS.TestData.Publish` (`modules/TestData.lua`) builds two session-only stores from the same sample universe — `NS.State.testHoldings` in `db.global.holdings`' shape (four of the sample's characters and the Warband, its thirty items, three currencies and gold) and `NS.State.testDaily` in `db.global.daily`'s shape (120 days of closes and gained/lost tallies, walked back from today's holdings with the sample rows' own flows folded in). Their read seams are `Holdings:ActiveStore` / `Holdings:View` and `Rollup:ActiveStore` (with `Rollup:Keys` for the picker), mirroring `Database:ActiveHistory`; the Reconciler, the `Apply*` / `Credit*` writes and the rollup writer stay on the live stores. The Timeline reads no `ledgerSince` in test mode, so it draws daily points and no marker. A stop clears both stores, and the same `OnDatasetChanged` repaint puts both tabs back on the live data.

Test mode is session-only: it resets on `/reload` and is never persisted (Standard debug-logging-§5, same rule as the debug flag). It stays on until something turns it off (the box, `/lh test`, combat, **Reset all settings** or `/lh resetall`) and does not depend on Lock frame; closing the window leaves it on.
