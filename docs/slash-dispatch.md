# Slash dispatch

One ordered table drives the entire slash UX: `NS.COMMANDS` in `settings/Schema.lua:896`. Each row is a **positional triple** — `{ name, description, handler }`, the shape `LibKa0s-Slash-1.0` reads — and the same rows dispatch verbs, generate the chat help *and* render the settings landing page, so adding a command is still a one-row append.

The table stays the **host's** and is passed into the library rather than owned by it, and that is the load-bearing decision in this seam rather than squeamishness: the settings landing page renders these same rows (`settings/Panel.lua:883`), so if the slash major owned the table, the options major drawing that page would have to resolve the slash major to read it — a real dependency cycle between two majors at load time. The table crossing between them as plain data is what keeps them independent. Each handler takes the rest of the line verbatim (never a `self`), so the seven verbs that are genuinely this addon's — `show` / `hide` / `toggle` / `config` / `debug` / `test` / `purge` — never leave the host, and adopting the library could not break them. The `diagnostics` row is the host's too, but only as a one-line hand-off: its handler calls `NS.DebugLog:RunDiagnostics()`, and the report is `LibKa0s-DebugLog-1.0`'s helper running this addon's sections (`modules/Diagnostics.lua`; see [debug.md](debug.md)).

`/lh` and `/loothistory` are both registered through AceConsole's `RegisterChatCommand` (`Sl:Register`, `settings/Slash.lua:513`) and dispatch to the same `Sl:OnSlash` handler — `/loothistory` is the long-form alias; all help text and docs use the short form.

The dispatcher is the library's (`libs/LibKa0s/Slash.lua:484`), bound onto `NS.Slash` by name at `settings/Slash.lua:477` because ~20 call sites across the schema table, the settings panel and the suite already reach for `NS.Slash:CliList()` and friends:

- Bare `/lh` (empty or whitespace-only) → runs the `config` row's handler with `""`, which opens the Settings panel on its landing page (standard slash-commands-§3, Slash **minor 11**). A host with no `config` row would get `Sl:PrintHelp` instead. Bare `/lh` never opens the loot window; use `/lh toggle` or `/lh show|hide`.
- `/lh help` → `Sl:PrintHelp`, the command index.
- `/lh <known>` → runs that row's `entry[3](rest)`.
- `/lh <unknown>` → `unknown command '<verb>'` then the help index.

Only the verb is lower-cased; the remainder (`rest`) keeps its original case *and* its internal spacing, so schema paths like `settings.qualityThreshold` survive unchanged through `/lh set <path> <value>`. The `debug` handler additionally lower-cases its own `on`/`off` subargument (`settings/Schema.lua:928`).

Every chat line routes through the single shared printer **`NS.Print`**, published from `LibKa0s-Core-1.0` in `core/CoreSetup.lua:263`, which prepends the mandated **cyan** `NS.PREFIX` `|cff00ffff[LH]|r` banner (`core/Namespace.lua:18`) and secret-stringifies each argument (events-frames-taint-§8) so a combat-protected "secret" value logs as `<secret>` instead of raising. Every file that emits chat does `local print = NS.Print` — call sites never call the global `print()`, never hand-write the tag, and never `..`-concatenate args before the printer. The dispatcher reaches it **late-bound** (`print = function(line) NS.Print(line) end`, `settings/Slash.lua:409`) so it survives `core/LootHistory.lua`'s reclaim of `NS.Print` from AceConsole's `:Print` mixin (architecture-§2). Cyan is the Ka0s house color every addon shares for its chat tag (slash-commands-§4).

## What is the library's, and what stays here

The dispatcher, the help header, the help rows, `LandingRows`, `BuildListLines`, `CliList` / `CliGet` / `CliSet` / `CliReset` / `CliVersion` (and the `CliResetAll` the host wrapper below delegates to), the two formatters (`lib.FormatRow`, `lib.FormatKV`) and the type-aware parser are all `LibKa0s-Slash-1.0`'s, wired through one `lib:New(descriptor)` call at `settings/Slash.lua:403`. The descriptor points the schema verbs at this addon's single write seam (`get`/`set`/`findRow`/`allRows`/`applyDefault` → `NS.Schema`), overrides `groupKey` to `row.group` (this addon is single-panel and has no concept of the library's default `row.page`), passes the `format` hook, and hands the Slash **minor 8** bracket (`bulkBegin` / `bulkEnd`) to `NS.Schema.BulkBegin` / `BulkEnd`, which mute the seam's per-row `[Set]` line inside `CliResetAll`'s walk and log the act once. The Options descriptor gets no bracket: nothing here calls `O.RestoreDefaults` or `O.RestoreAllDefaults`.

Host-owned, and each for a reason:

- the seven `StaticPopupDialogs` confirms (`settings/Slash.lua:7`) — this addon's destructive gates, never the library's;
- `Sl:ResetEverything` (`settings/Slash.lua:202`) — the total reset behind the Master controls tab's **Reset all settings** button — options-ui-§12's global reset, and a superset of the `resetall` verb, which never touches history. The two being different acts is a **ratified** divergence from that rule's opening sentence — a register row (`options-ui-§12`, 2026-09-02) in [ARCHITECTURE.md](ARCHITECTURE.md#documented-deviations), reasoned in [schema.md](schema.md#reset-semantics);
- `Sl:CliResetAll` (`settings/Slash.lua:508`) — a **wrapper**, not a re-export, because the `blacklist` / `whitelist` / `currencyBlacklist` id-lists are a structural registry with no schema row, so the library's row walk cannot see them; it clears them by calling their one writer, `NS.Filters:ClearAll` (architecture-§5);
- `Sl.FormatSchemaValue` (`settings/Slash.lua:251`) — passed as the descriptor's `format` hook (Slash **minor 5**), holding **only** the `type = "table"` branch and handing everything else straight back to `lib.FormatValue`;
- `Sl:Register` (`settings/Slash.lua:513`) — the chat-command registration.

If the library is absent, `settings/Slash.lua`'s `if not lib then` branch degrades rather than errors: `/lh` is still registered, the seven host verbs still dispatch through the same positional walk, and every library-owned verb answers `NS.LIBKA0S_MISSING` plus its own consequence — *"…, so the slash command interface is unavailable."*

A **bare `/lh` prints help on that path** (slash-commands-§3). The stub mirrors the library's bare rule (run the `config` row, else help), but it looks `config` up through the same `UNAVAILABLE_WITHOUT_LIB` set described below: `config` is registered here and can only decline, so bare falls back to help rather than printing the "unavailable" line alone. That help lists the eight verbs that still work — `show`, `hide`, `toggle`, `enable`, `disable`, `debug`, `test`, `purge` — under a header carrying the shared cause clause.

**`enable` / `disable` work on that path** (`options-ui-§1` route (a)). Both delegate to `CliSet`, and the degraded `CliSet` writes exactly one path: `settings.enabled` with a literal `true` or `false`. The Options composer is the stub there, so the Master controls block is **empty** and there is no row; the write lands anyway, through the Schema seam's `writeThrough = { "settings.enabled" }` list, which stores a listed row-less path raw and runs **no** `onChange`. So the stub then calls `NS.Schema.OnEnabledWritten()` itself — the same function the row's `onChange` calls on a full load (the latch through `NS.OnEnabledChanged`, then `SettingsChanged`) — and acknowledges with the `set` shape, `settings.enabled = false`, re-read from the store. Every other `set` (another path, or a value that is not `true`/`false`) still answers the "unavailable" line, which is why `set` itself stays out of the help: only the enable path writes.

**The refusal line is the library's, byte for byte.** `Sl.DISABLED_LINE_FORMAT` is set on **both** paths (so the Slash surface-parity case stays symmetric): `lib.DISABLED_LINE_FORMAT` when the library is present, and otherwise the one library string `slash-commands-§1` lets a stub carry verbatim. The degraded `Sl.DisabledLine()` formats it with the library's own arguments — `NS.BRAND` and `/lh enable` — and `tests/test_slash_degraded.lua` pins both the template (`Kit.assertLibraryConstant`) and the rendered line against the live library.

**`resetall` says what it did.** The three id lists have a writer that needs no library, so the degraded `CliResetAll` still clears them through `NS.Filters:ClearAll()` and prints the count it returned: `filters reset (3 ids cleared); other settings need the LibKa0s library.` (`1 id` in the singular). The schema rows need the library's walk, which is the second clause. The one host verb left with no library-absent line is `test`, which toggles `NS.BrowserTable` directly and needs no row.

**`diagnostics` answers, but does not work, on that path.** Its row is host-owned, so it still dispatches, and `/lh debug diagnostics` reaches the same call. The report is written into the LibKa0s console, though, so with no library the call lands on the DebugLog stub, which prints the collection's library-absent line, `/lh diagnostics is unavailable: the LibKa0s library did not load.`, writes nothing and returns 0 (`debug-logging-§14`). It is in `UNAVAILABLE_WITHOUT_LIB` for `config`'s reason, so the degraded help does not offer it. `tests/test_slash_degraded.lua` dispatches both forms library-less.

The help list is rendered by **subtraction** from `NS.COMMANDS`: one set, `UNAVAILABLE_WITHOUT_LIB`, names the verbs not to offer, so adding a host verb cannot leave the degraded help behind. Membership is *cannot answer here*, not *went through the library* — `config` is host-owned and still fails, because its handler calls `NS.Panel:Open` and lands on the `Options` stub's declining `OpenOptionsPanel`, so it is subtracted too rather than advertised and then refused. The stub also exports `HelpHeader`, which the live seam publishes and it did not: `tests/test_surface_parity.lua`'s `Kit.assertSurfaceParity` case is what now holds the two surfaces to the same member set.

## Generated help

`Sl:PrintHelp` prints the header from `Dispatcher:HelpHeader()` (`libs/LibKa0s/Slash.lua:590`) — version, an **em dash**, then the alias clause composed from the descriptor's `slashAliases`:

```
[LH] v1.4.0 — slash commands (|cFFFFFF00/loothistory|r is an alias for |cFFFFFF00/lh|r)
```

then one prefixed row per `NS.COMMANDS` entry, each **indented two spaces** so it sits under that header (`Sl:HelpRows`, `libs/LibKa0s/Slash.lua:584`). A row is a gold command, an em dash with a **single space either side**, and a white description — upper-case hex, because that is the library's:

```
[LH]   |cFFFFFF00/lh show|r — |cFFFFFFFFOpen the window|r
```

**Convergence — one command-row formatter, chat and panel.** The settings landing page used to carry its own version of that row: double spaces around the em dash, the dash itself wrapped in white, the description left bare — divergent from the chat help two files away for no reason anyone recorded. Both now render through `lib.FormatRow` (`libs/LibKa0s/Slash.lua:126`) via `Sl:LandingRows` (`settings/Slash.lua:500`), which is the chat form minus the indent — a leading indent reads as a mistake on a panel label, not as structure. User-visible on the landing page: single spaces, no color span on the dash, the description now white. Deliberate; do not "fix" it back (closed issue [LIBKA0S-09](https://github.com/tusharsaxena/LootHistory/issues/24)).

Because the help index, the landing page and the dispatcher all read the same table, they can never drift.

## Schema-reflecting CLI

`get` / `set` / `list` / `reset` are thin CLI mirrors of the settings Schema (`settings/Schema.lua`); they resolve against `NS.db.global` and route all writes through the `Schema:Set` seam, so a CLI write and a panel widget behave identically (validate → deep-copy → `onChange`). See [settings-panel.md](settings-panel.md) and [schema.md](schema.md).

`list`, `get`, `set` and `reset` share the Ka0s canonical output shape (slash-commands-§5), produced by two shared helpers so the four can never drift:

- **`Sl.FormatKV(path, valueStr)`** — re-exported straight from `lib.FormatKV` (`libs/LibKa0s/Slash.lua:132`): the colored `key = value` line, gold key, white value, no trailing colon. Identical in shape to what this file used to own, with the hex digits now in the library's **upper** case — `|cFFFFFF00settings.enabled|r = |cFFFFFFFFtrue|r`.
- **`Sl.FormatSchemaValue(row, v)`** — the type-aware value renderer. `type = "table"` is not one of the library's four types, so `lib.FormatValue` would fall through to Core's `SafeToString`, probe `table.concat`, fail, and answer `<secret>` — telling a user that `settings.excludedSources` is combat-protected. That one branch lives here (a sorted `{KILL, MAIL}` key set, or `(none)` when empty) and everything else is handed back to `lib.FormatValue` (`libs/LibKa0s/Slash.lua:196`): a row's optional `fmt` formats numbers (`windowScale` `%.2fx` → `1.00x`), booleans → `true`/`false`, enums stay raw. It is wired in as the descriptor's `format` hook, so the CLI and the settings panel cannot render the same value two ways.

- **`get <path>`** — `Sl:CliGet`. Prints the single-line `FormatKV` echo for the path. A missing argument prints `Usage: /lh get <path>`; an unknown path prints `Setting not found: <path>`.
- **`set <path> <value>`** — `Sl:CliSet`. Looks up the row (unknown → `Setting not found: <path>`), parses the raw text by the row's declared `type` through `lib.ParseValue` (see below), writes it via `Schema:Set` — which validates and fires the row's `onChange` — then **re-reads the stored value** and echoes it via `FormatKV`, which is the only way a clamp is visible to the user. **A refused write prints the seam's reason instead** (Slash minor 15): the descriptor's `set` returns `Schema:Set`'s `false, err`, so a value the row's `validate` rejects answers `Invalid value for <path>` (plus the reason, when it says more than that) and no echo, rather than echoing the unchanged value as if the write had landed. `applyDefault` deliberately returns nothing, so `reset` never reads the `minimap.shown` bulk veto as a missing default. A missing argument prints `Usage: /lh set <path> <value>  (try /lh list)`.
- **`list`** — `Sl:CliList` (via the pure, testable `Sl:BuildListLines`, `libs/LibKa0s/Slash.lua:641`). Prints a green `|cff33ff99Available settings|r` header, then one azure `  |cff3399ff[group]|r` header per schema group **in declaration order** (LootHistory's single-panel section headers stand in for the standard's `[page]` headers, via the descriptor's `groupKey`), then a four-space-indented `FormatKV` row per setting. New settings appear automatically as schema rows are added. These two headers keep their **lower**-case hex deliberately — only the command-row and key/value formatters converged on upper case, and recasing the rest would be a user-visible change nobody asked for.
- **`reset <path>`** — `Sl:CliReset` (`libs/LibKa0s/Slash.lua:722`). Resolves and applies the row's default through `Schema:Default` (deep-copied) + `Schema:Set`, then echoes the **same `FormatKV` line** every list row, get echo and set echo uses — `|cFFFFFF00settings.excludedSources|r = |cFFFFFFFF(none)|r`, not a bespoke `<path> reset to <value>` sentence. The path is not lower-cased (folding it would resolve a setting the user did not name). A missing argument prints `Usage: /lh reset <path>`; an unknown path prints `Setting not found: <path>`.
- **`resetall`** — `Sl:CliResetAll`. Clears the `blacklist` / `whitelist` / `currencyBlacklist` id-lists via `Filters:ClearAll` **first**, then walks every schema row back to its default and acknowledges `All settings reset to defaults` (capital A, the library's string), so the last line printed reads as the summary of everything that happened. This is **non-destructive** (**no confirmation prompt**) — it does not delete recorded history, and leaves `savedView` / window geometry alone. See [schema.md](schema.md#reset-semantics). It logs one `[Set] reset all: N rows` line and no per-row `[Set]` (debug-logging-§10). N is the seam's tally of rows whose stored value changed, not the library's `count` of rows walked, so a reset of settings already at their defaults logs `0 rows`. A row that raises part-way still gets the one line, with ` (stopped by an error)` appended; the library then re-raises, and the seam's mute is already released. A `BulkEnd` with no open bracket logs nothing. The General page's **Defaults** button reaches the same walk and logs the same line. **`minimap.shown` is exempt from both** (launcher-§3, standard v2.54.0; renamed from `minimap.hide` in v2.65.0, whose stored key it still is): the descriptor's `applyDefault` is `NS.Schema:ApplyDefault`, which skips any row path keyed in `NS.Schema.RESET_EXEMPT` while a bulk bracket is open — so the row is neither written nor counted, and the button a player hid stays hidden. A single `/lh reset minimap.shown` is not a bulk act and still resets it. `/lh get|set minimap.hide` answers `Setting not found`: the stored key is no row's path.

- **`enable` / `disable`** — slash-commands-§2's two reserved verbs, and **aliases rather than a second switch**. Each delegates to `Sl:CliSet` with `settings.enabled` and a literal, so the write is the Master controls **Enable Loot History** row's own, through `Schema:Set`, with the row's `onChange` firing the `SettingsChanged` fan-out the Collector listens for. They hold **no state of their own** — no second key, no session flag, no `NS.enabled` local — so the checkbox and the verbs can never show the player two different answers. Delegation rather than a handler is what makes the acknowledgment slash-commands-§5's `set` shape by construction, re-read from the store rather than echoed back; `/lh enable` and `/lh set settings.enabled true` print the identical line, and `tests/test_slash.lua` asserts that.

  **The dispatcher survives the disabled state**, which is what stops the pair being one-way (§2). Nothing gates *dispatch* on `settings.enabled`: `Sl:Register` runs from `OnInitialize` unconditionally, the chat command is never unregistered, and `NS.COMMANDS` is never torn down. A bare `/lh`, `help`, `version`, `list` and `enable` all answer with the addon off. **The stored flag no longer has a second reader in `modules/Collector.lua`** — that was the draw gate (`anti-patterns #85`), and the capture path is unregistered rather than gated now; the flag's readers are the latch (`NS.OnEnabledChanged` → `NS.Lifecycle:Set`) and this dispatcher's `isEnabled`. See [disabled-state.md](disabled-state.md).

- **The disabled slash surface is UNCHANGED, and that is the ruling** (slash-commands-§7, standard v2.57.0, LibKa0s v1.41.0 / Slash minor 13). The standard narrowed it to `enable` and `help` at v2.56.0 and **reversed** that at v2.57.0: while disabled, `config` and the bare `/lh` open the panel, `version` prints, `debug` runs, and the whole schema CLI reads and repairs settings. The case that settled the reversal was the smallest one — `/lh` on a disabled addon answering a refusal instead of opening the one surface it can be switched back on from by hand. The descriptor therefore passes **no `liveVerbs`**: it takes `lib.LIVE_VERBS`, so the set is the library's rather than a copy of it that could drift back to the narrowed three. `tests/test_disabled.lua` asserts the addon's own restated copy (`LIVE_WHILE_DISABLED`, in `settings/Schema.lua`) agrees with it.

- **`lock` / `unlock` are reserved here and NOT registered, which is a MAY declined** (slash-commands-§8). This addon has lock functionality — the Master controls **Lock frame** checkbox at `settings.locked`, which covers the History window and the export modal — so the option is open to it, and it is not taken: the checkbox is the whole surface. §8 names Loot History as one of the three addons in that case and calls it “the case the MAY exists to leave alone”. **Declining a MAY is not a deviation and owes no register row**; the register is for ratified departures from a MUST or a SHOULD, and filing a declined MAY there would bury the real rows under noise. Both verbs stay reserved here as everywhere, so neither can be given a second meaning.

- **A disabled addon refuses a FEATURE verb** (slash-commands-§2's SHOULD, which survived the reversal and is the only refusal in the disabled state). While `settings.enabled` is `false`, `show` / `hide` / `toggle` / `test` / `purge` — the verbs that draw, preview and destroy — answer on **one** tagged line naming `/lh enable` and **do nothing else**: no partial work, no side effect, no second line. Everything else keeps answering, and that list is §2's verbatim: `help`, `config`, `version`, `enable`, `disable`, `debug`, `perf`, `diagnostics` and the schema CLI (`get`, `set`, `list`, `reset`, `resetall`). A player must be able to read and repair settings and reach the panel while the addon is off, and `enable` above all. (`perf` is on the list although this addon does not register it — performance-§12, a ratified deviation — because the verb stays reserved here as everywhere.)

  **One gate, at the table.** The wrap is applied to each feature handler as `NS.COMMANDS` is built (`settings/Schema.lua`'s `gateFeatureVerbs`, over the `LIVE_WHILE_DISABLED` set), not pasted into each verb and not placed inside `Sl:OnSlash`. The table is the one seam common to **both** dispatchers this addon has — the library's, and the positional walk the library-less install falls back to — and it is also what a direct `entry[3]("")` call reaches, so there is no route into a verb that skips the gate and a verb declared tomorrow is gated by default. The triple keeps its `name` and `description`, so the help index, the landing page and every count over `NS.COMMANDS` are untouched. **The refusal WORDING is the collection's, not this addon's** (slash-commands-§7): one shape, built by `LibKa0s-Slash-1.0` from `NS.BRAND` and the slash — `Ka0s Loot History is disabled — enable it with /lh enable`, the command in the help index's gold, no trailing period — and reached through `NS.Slash.DisabledLine()` by the verb gate, the one call site that prints it — the launcher's left click printed it too until Launcher minor 4 (LibKa0s v1.58.0) retired that refusal. The launcher's menu entries **Test mode** and **Show window** run the `test` and `toggle` handlers themselves (`entry[3]`), so a client that dispatches a grayed entry still meets this gate. It was `NS.L.SLASH_DISABLED_VERB` until v1.41.0; that string is gone from `locales/enUS.lua`, because the library's own descriptor says in as many words that an `L` override does not reach this line. The switch itself is read through `NS.AddonIsOff()`, which reads `Schema:Get("settings.enabled")` and never `db.global` directly, so the verbs and the Master controls checkbox can never answer from two places. It reads the **stored** switch rather than `NS.IsStoodDown()`, because a perf capture is a reason to be inert and never a reason to refuse a verb.

**Convergence — `reset` takes a path, at no cost.** The library's `reset` is deliberately path-scoped with no page-shaped form (a page is a property of a settings panel, and every such panel already carries a Defaults button). This addon was already path-scoped and already had `resetall`, so nothing was lost and no confirmation popup had to be re-anchored: the destructive verb here is `/lh purge` (and the panel's **Reset all settings**), both still routed through `StaticPopup_Show`. A page or tab name is refused rather than silently resetting a section — `/lh reset Capture` answers `Setting not found: Capture`.

### The type-aware parser

`lib.ParseValue` (`libs/LibKa0s/Slash.lua:401`) replaces bare coercion, on the principle that a CLI which silently accepts a value it cannot honor is worse than one that refuses. Failure prints `Invalid value for <path>` and then the reason on a two-space-indented second line; the old value survives untouched.

- **`bool`** — `true`/`1`/`on`/`yes` and `false`/`0`/`off`/`no`. Anything else is **refused** rather than silently stored as `false`: `/lh set settings.enabled maybe` → `Invalid value for settings.enabled` / `  expected true/false/on/off/1/0/yes/no`.
- **`number`, plain (a `Slider` row)** — **clamped** to the row's `min`/`max`, because a user typing a scale larger than the panel allows means "as large as it goes". `/lh set settings.windowScale 99` stores `1.6` and echoes `settings.windowScale = 1.60x`.
- **`number`, enumerated (a `Dropdown` row with `values`)** — **constrained**, not clamped: clamping would land between two entries and the renderer would have no label for what is stored. `/lh set settings.qualityThreshold 9` → `Invalid value for settings.qualityThreshold` / `  allowed values: 0, 1, 2, 3, 4, 5, 7`.
- **`table`** (the two set-valued rows, `settings.excludedSources` and `settings.auction.capture`) — readable but not writable from the CLI; the parser answers `unknown setting type 'table'`. They are edited from the settings panel's General ▸ Capture and General ▸ AH Price tabs.

## Session-only `debug`

The `debug` handler (`settings/Schema.lua:928`) drives the debug console independently of the logging flag:

- `/lh debug` → `DebugLog:Toggle()` — flips the console **window** only; the logging flag is untouched.
- `/lh debug diagnostics` → `DebugLog:RunDiagnostics()`, tested **first** and in any case, so neither `on`/`off` nor the toggle can claim the word. The same call as the `diagnostics` verb, so the two forms cannot diverge. No shorter word (`diag`, `dump`) reaches it: those fall through to the window toggle like any word this verb does not know. See [debug.md](debug.md).
- `/lh debug on` / `/lh debug off` → `DebugLog:SetEnabled(true/false)` — sets the session-only logging flag `NS.State.debug`. Capture runs even with the window closed.
- `/lh debug events` → prints `rejected events: <names>`, or `rejected events: none` — the event names this client refused at registration, read off `NS.RejectedEvents` (events-frames-taint-§1; see [ARCHITECTURE.md § Event subscriptions](ARCHITECTURE.md#event-subscriptions)). It touches neither the window nor the flag, and answers while the addon is disabled.

`NS.DebugLog` is `LibKa0s-DebugLog-1.0`, wired in `core/DebugLogSetup.lua`. The flag is never persisted to SavedVariables and resets to off on every `/reload`; the logging flag is deliberately **not** a Schema row (`settings/Schema.lua:395`), while the console **window's** visibility *is* — the session-only `state.debugConsole` row. See [testing.md](testing.md) for the debug console and the `/lh test` synthetic dataset.

## Confirm dialogs

Seven `StaticPopupDialogs` entries are registered once at load, in-game only (`settings/Slash.lua:7`):

- **`KA0S_LOOTHISTORY_PURGE`** — the confirm behind `/lh purge`. The `purge` command calls `StaticPopup_Show("KA0S_LOOTHISTORY_PURGE")` (`settings/Schema.lua:966`); accepting runs `Database:Purge()` and prints `history purged`. If `StaticPopup_Show` is unavailable (headless), it purges directly. The Settings panel's "Purge history…" button raises the same popup (`settings/Panel.lua:113`).
- **`KA0S_LOOTHISTORY_PRUNE`** — the confirm behind a shorter **Keep history for** (`settings/Slash.lua:23`), from the panel dropdown or `/lh set settings.retentionDays <n>` alike, raised by the row's `onChange` (`S:OnRetentionChanged`) only when the new value would delete records. Its text names the new retention and the count. Accepting runs `Database:PruneOld()`; declining writes the previous retention back through `Schema:Set` and prints `retention kept at <label>; no records were deleted.` With no `StaticPopup_Show` (headless) it prunes directly. See [schema.md → *Retention prune*](schema.md#retention-prune).
- **`KA0S_LOOTHISTORY_RESETALL`** — the confirm behind the Master controls tab's **Reset all settings** button (options-ui-§15 names it; it read "Reset Everything" on the Maintenance tab before that), *not* the `resetall` slash verb. The dialog key keeps its historical name, and its text — options-ui-§12's second canonical wording, the one for an addon with no profile — discloses both effects. Accepting runs `Sl:ResetEverything` (`settings/Slash.lua:202`), which wipes history (`Database:Purge`), restores every setting **and** clears the filter lists (`CliResetAll`), then drops `savedView` to stock (`Browser:ResetView`) and recenters the window (`Browser:ResetWindow`), then refreshes the panel. This is the total destructive reset; the `/lh resetall` verb only resets settings + the id-lists and prompts for nothing.
- **`KA0S_LOOTHISTORY_CLEAR_BLACKLIST`** / **`KA0S_LOOTHISTORY_CLEAR_WHITELIST`** / **`KA0S_LOOTHISTORY_CLEAR_CURRENCY`** — the confirms behind the Filters tab's per-list **"Clear all"** buttons (item blacklist, whitelist, and the currency blacklist). Accepting calls `Filters:ClearList(<list>)`; the panel refreshes via its `HistoryChanged` listener. Non-destructive — clearing a list only empties its id-set; stored history is untouched (blacklisting affected future captures only).
- **`KA0S_LOOTHISTORY_CLEAR_FILTERS`** — registered (`settings/Slash.lua:88`) but **no longer raised by anything**. It was the confirm behind the Filters *sub-page*'s own top-right **"Defaults"** button (its default state is empty lists); R6 folded Filters into General's strip, and the one page-wide Defaults button left routes through `P:RestoreDefaults` → `Sl:CliResetAll`, which clears all three lists as part of a full settings reset and prompts for nothing. Accepting would still call `Filters:ClearAll()`, clearing the blacklist, whitelist **and** currency blacklist in one action; non-destructive — stored history is untouched. A `grep -rn "KA0S_LOOTHISTORY_CLEAR_FILTERS" core modules settings` finds the registration and no `StaticPopup_Show`.

See [schema.md](schema.md) for what `purge` and the reset actions clear in `LootHistoryDB.global`.
