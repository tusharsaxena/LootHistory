# Module map

Where each responsibility lives in the source tree, plus the TOC load order and the AceAddon lifecycle hooks. `LootHistory.toc` is the source of truth for load order — match this map to it before editing. 60 authored source files (every non-`libs/` TOC entry) across `core/`, `defaults/`, `locales/`, `settings/`, `modules/`; the internal-only terms **Collector** (capture) and **Browser** (view) are used throughout.

## File roles at a glance

One row per authored file, grouped as the TOC loads them; the numbered entries under [TOC load order](#toc-load-order) carry the detail and the line cites.

| File | Role |
|---|---|
| `core/Compat.lua` | **Loads first.** The compat firewall: every deprecated/varying-API shim gated by direct `C_*`/global presence (no `WOW_PROJECT_ID` game-flavor branching — Retail-only) — GUID decode + `UNIT_KINDS`, item/map/zone info, active keystone level, quality-from-link fallback. `Compat.GetSpellName` is **`LibKa0s-Compat-1.0`**'s member, wired as a field, with the reader stub (`nil`) when the library is absent. |
| `core/SimSeam.lua` | The **`LibKa0s-Sim-1.0`** answer seam (LootHistory#37). **LOAD-BEARING: straight after `core/Compat.lua`**: `Sim:NewSeam` wraps every `NS.Compat` function member in place at file load, except the pure ones (the text and parse helpers, the tooltip family, the four hook installers), and guards `ListCurrencies`, the one member that changes client state (while a simulation runs it answers the simulated world's list and never expands a currency header). Publishes `NS.SimSeam` and `NS.SimHost` (the host's own table, OWNER_SCOPE C.4, with the reference stub factories `NewSeamStub` / `NewSimStub`); without the library nothing is wrapped and `NS.SimSeam` is the inert stub. `tests/test_sim_seam.lua` asserts `NS.SimSeam:Unwrapped()` is empty once the whole addon has loaded. |
| `core/EnvSetup.lua` | The **`LibKa0s-Env-1.0`** seam: `NS.Meta(field)`, `NS.Version()`, `NS.PlayerMapID()` and `NS.Zone()` — the TOC read behind `/lh version` and the where-am-I stamp on every stored row. Took over `core/Compat.lua`'s map, zone and TOC-metadata shims; the map and zone ladders have since returned to Compat as `Compat.PlayerMapID`/`Compat.Zone` (still Env-first) so the simulator's seam can reach them, and `NS.PlayerMapID`/`NS.Zone` forward there at call time. It is handed `addonName` (the addon **folder**, the first vararg — not `## Title`) because a vendored library cannot know which folder it sits in. **TOC position is conventional, not load-bearing**: nothing resolves here beyond the LibStub lookup. `NS.Zone` answers two strings and **never nil** — `""` buckets with nil on purpose in `Database:Stats`, the Zone filter and group-by-zone. |
| `core/ItemSetup.lua` | The **`LibKa0s-Item-1.0`** seam: `NS.Item` with `ItemIDFromLink`, `BonusIDsFromLink` (Item minor 3, read by `modules/Export.lua`'s `WowheadLink`), `QualityFromLink`, `QualityLabel` and `LoadItem`. **Its TOC position is load-bearing** — `core/Constants.lua` calls `QualityLabel` at **file load** to build the quality threshold labels, so it must sit above Constants. The **resolver did not move**: `Compat.GetItemInfo` still guesses name and quality for an uncached id (this addon would rather store an approximate row than lose the drop). A degraded install gets the same five primitives locally — the quality they write is **stored**, not just drawn. |
| `core/MediaSetup.lua` | The **`LibKa0s-Media-1.0`** seam: `NS.Icon` / `NS.MediaFont` / `NS.IconMarkup`, and `Media.RegisterLSM(addonName)` at **file load**. **Its TOC position is load-bearing** — it must sit above `core/Constants.lua`, which resolves `FONT_MONO` from `NS.MediaFont` at load. Paths are extensionless and point into the vendored payload (`libs/LibKa0s/media/`); `nil` is a real answer twice (no library, no such name), and every call site keeps its Blizzard rung underneath. This addon ships no font and no icons of its own. |
| `core/Constants.lua` | `SourceType` enum, `SourceOrder`/`SourceLabel`, `SOURCE_IMPLEMENTED` (coverage gate), `Confidence`, `CONTEXT_TTL`, `ITEMCLASS_QUEST` (Quest item-class id for the capture filter), `CURRENCY_TYPE` (the `"Currency"` type label for currency rows), `AUCTION_KEYS` (the AH-price key catalog), `RECORD_ADDED_COALESCE` (`0.2`s — the `RecordAdded` repaint window), `FONT_MONO_NAME` / `FONT_MONO` (resolved from `NS.MediaFont` at load — see `core/MediaSetup.lua`), quality/retention/source option tables. |
| `core/Namespace.lua` | Bootstrap: sets `NS.name`, `NS.version`, `NS.PREFIX`. (`NS.L` is published by `locales/enUS.lua`; module tables self-publish idempotently.) |
| `core/State.lua` | Runtime state: `lootContext`, encounter/keystone context, session flags, session-only `debug`, and the session-only `testRecords` (the `/lh test` synthetic dataset). |
| `core/Util.lua` | Pure helpers: date-range (`RangeFrom`) + time/money/byte formatting, self-loot string parsing, `PlayerKey`, dotted-path split, and **`Util.Coalesce(fn, delay)`** (also published as `NS.Coalesce`) — the burst coalescer behind the `RecordAdded` repaint. It clears its pending flag **before** running the body, so a raise inside `fn` cannot wedge the trigger and leave a surface that never repaints again; with no `C_Timer` it runs straight through. |
| `core/Ledger.lua` | `NS.Ledger`, the timeline ledger's pure primitives: `ThingKey` / `ParseThingKey` (`i:<id>`, `c:<id>`, `g`), `Diff` (signed per-key change between two count maps) and `DirSign`, plus the daily-rollup cell math (`DayKey`, `RowThingKey`, `RollupClose` / `RollupFlow`, `PruneDaily`, `ForgetHolderDaily`). No WoW API and no SavedVariables, so what the Reconciler decides is pinned headless. Conventional TOC position, after `core/Util.lua`. |
| `core/CoreSetup.lua` | The **`LibKa0s-Core-1.0`** seam. Publishes the shared **secret-safe chat printer** — `NS.Print` / `NS.Format` / `NS.Util.print` (+ `IsConcatSafe` / `SafeToString`), the single seam every module prints through (events-frames-taint-§8), reclaimed from AceConsole's `:Print` in `core/LootHistory.lua` — which is why this file publishes to **both** keys. It also publishes **`NS.LIBKA0S_MISSING`**: one cause clause, appended to by every other LibKa0s seam in the addon, set outside the `if not lib` branch because they read it on both paths. A cross-file contract, not an implementation detail. Also publishes **`NS.ApplySkin`** and **`NS.MakeCloseButton`** — the latter wrapped once so `lib.MakeCloseButton`'s **third** argument, this addon's folder name, is passed from every close control it builds; a two-argument passthrough would run, return a button, stay green in every suite, and draw a multiplication sign forever (anti-patterns #64). And **`NS.MakeResizable`**, the History window's corner grip: `Core.MakeResizable` by reference (Core minor 10's `canResize` gates it on Lock frame, `onResizeStop` saves once per release), or the pre-library grip on a degraded install (#33). |
| `core/SkinSetup.lua` | The **`LibKa0s-Skin-1.0`** seam (skinning-§3): registers the owner `"LootHistory"` at file load with this addon's read and write seams and publishes **`NS.Skin`**, the owner's facade (`Skin:For`), which every surface paints and reads its colors through. **`NS.SkinChoice()`** reads the stored `settings.appearance.source` / `.skin` through `NS.Schema:Get` (Ka0s Default before `NS:InitDB`), **`NS.WriteSkinChoice(source, skin)`** writes both through `NS.Schema:Set`, and **`NS.ApplySkinChoice(source, skin)`** moves the applied skin with `Skin:SetChoice` (resolve, repaint every recorded frame, then `OnLooksChanged`): with no argument the stored pair (`addon:OnInitialize` right after `NS:InitDB`, and first in `NS.OnProfileEvent`), with one half nil only the other (each Appearance row's `onChange`, so a tab pick or another addon's copy is one effective change). Also `NS.SKIN_OPTIONS` / `NS.SKIN_SOURCE_OPTIONS` (the two rows' values) and `NS.SKIN_FALLBACK`, the host copy of the Ka0s Default tokens the degraded facade answers (and `core/CoreSetup.lua`'s pre-library edge reads), plus **`NS.SkinColor(name)`**, a color token as a call site writes it (three components when opaque), so a literal that became a token keeps its arity, **`NS.SkinEscape(name)`**, a token as a `|cffrrggbb` escape rounded to the byte (so `|cffff5555` stays those bytes on Ka0s Default), and **`NS.QualityColor(q)`**, an item quality's color: the skin's `q.*` override where it sets one, else the client's `ITEM_QUALITY_COLORS`. Without the library `NS.Skin` is a host table answering every facade name: `Shell` is `NS.ApplySkin`'s pre-library edge, `TitleBar` / `Divider` / `Button` / `MenuFrame` / `Text` / `Token` / `Color` draw or answer from the host copy, and every other primitive is a no-op. Load-bearing: below `core/CoreSetup.lua`, above `core/WidgetsSetup.lua`, every module and `settings/Schema.lua`. |
| `core/Dispatch.lua` | **One capture event table and one read-side hook table** (LootHistory#37). `NS.EVENT_ROWS` (ordered `{ event, owner, target, fn, unit? }`, target `bus` / `out` / `ledger` / `spell`) and `NS.HOOK_ROWS` (ordered `{ name, owner, fn, tbl?, install? }`), appended at file load by Attribution, AttributionOut, Collector and Reconciler through `NS.EventRow` / `NS.HookRow`. `NS.RegisterRows(owner, targetObj, targetKey)` / `NS.UnregisterRows(owner)` replace the four hand-written registration lists and keep `row.registered` true only while a registration is live; `NS.InstallHookRows(owner)` installs an owner's hooks under the module's once-per-session latch. Every live handler is `NS.Deliver` / `NS.DeliverHook`, with one hook point, `NS.RealEventFilter` (nil until the simulator sets it). `NS.DeliverAll(event, ...)` walks the registered rows (or `hook:<name>` the installed hook rows) in order, each under `pcall`, and answers the count. **Its TOC position is load-bearing**: above every module, which append rows at file load. |
| `core/LifecycleSetup.lua` | The **`LibKa0s-Lifecycle-1.0`** seam (`slash-commands-§7`): **`NS.Lifecycle`**, the one latch every reason to be inert holds (`NS.HOLD_DISABLED`, `NS.HOLD_PERF`), plus **`NS.StandDown`** / **`NS.StandUp`** (every registration this addon owns torn out and rebuilt), **`NS.After`** / **`NS.CancelDeferrals`** / **`NS.CancelDeferral`** (cancelable deferrals, all or one handle), **`NS.IsStoodDown`**, **`NS.AddonIsOff`** (the stored switch the slash gate and the launcher ask), **`NS.RefusalLine`** (the addon's one refusal-by-hold helper: the disabled line while the stored switch is off, *Not available during a performance capture.* under the perf hold alone, otherwise nil; the Show window key binding asks it, launcher-§6), **`NS.OnEnabledChanged`** and **`NS.BindLifecycle`** (AceDB's three profile callbacks onto `NS.OnProfileEvent`). TOC position is **conventional**: nothing resolves at load, and the latch is first touched from `addon:OnEnable`. Without the library it degrades to a hold set and two edges written out locally. See [disabled-state.md](disabled-state.md). |
| `core/PerfSetup.lua` | The addon's half of **`LibKa0s-Perf-1.0`** (performance-§1): the five in-combat buckets (`lootLine`, `currencyLine`, `moneyLine`, `spellCast`, `ledgerEvent`), the `perf` hold on the latch and the `/lh perf` handler. TOC position directly after `core/LifecycleSetup.lua` is load-bearing. See [performance.md](performance.md). |
| `core/WidgetsSetup.lua` | The **`LibKa0s-Widgets-1.0`** seam: every chrome factory (the dropdown and its menu, the search box, its suggestion list, the mode strips) names this addon as the widget's skin **`owner`** (Widgets minor 16), so the library paints it for the skin `core/SkinSetup.lua` registered; **`NS.MakeDropdown(parent, width)`**, **`NS.HasWidgets()`**, **`NS.CloseMenu()`** and **`NS.CopyWindow(descriptor)`** and **`NS.MakeLineChart(parent, opts)`** (the Timeline's chart; nil without the library) with **`NS.LineChartChrome()`** (its published paddings, read by the in/out strip while the chart is cleared) and **`NS.MakeAutocomplete(editBox, opts)`** (the Search box's suggestion list on every tab, P9; nil without the library) and **`NS.MakeSearchBox(parent, width, opts)`** (the filter bar's Search box, `W.SearchBox` with the gold focus line, LibKa0s#52; nil without the library or its SearchBox, where the bar builds a plain box) and **`NS.MakeTestStrip(parent, text, kind)`** with **`NS.TestStripReserve()`** (the History window's mode strips under the filter bar, `W.TestStrip` with the `info` mark in its amber test or cyan sim flavor, LibKa0s#48 / LootHistory#36 #37, and the room the panes give it: the library's `TEST_STRIP.HEIGHT` plus this addon's 2 px gaps; nil and 0 without the library, where the title badge alone marks the mode) — the export copy window, a lazily-built handle rather than a frame, so a session that never exports creates nothing. One factory for all ten flat dropdowns this addon draws — the filter bar's nine and the export modal's Data Set picker — and it is where the widget's art is resolved: a vendored library cannot know which addon folder it sits in, so `chevron` and `check` are looked up through `NS.Icon` **here** and passed in as parameters, once, rather than at each call site. It passes **no `glyphFont`** and that is a decision: the field is a *precondition* for any option carrying `opt.glyph`, no option this addon builds carries one (the multi-select tick is markup the library splices itself, the Character rows' class icons are markup folded into a label), and a proportional face passed for a glyph nothing draws renders a box. It replaced 208 lines of `modules/Browser.lua` — the collection's third copy of one widget. `nil` is a real answer both ways: `NS.MakeDropdown` returns nil with no library and both surfaces refuse to draw rather than build a control that opens no menu, and `NS.CloseMenu` becomes a no-op. **`NS.HasWidgets()`** is the same question asked with nothing built — a surface whose only control is a dropdown would otherwise have to create its window to learn the answer, and `modules/Export.lua`'s window carries a global name, so a build-and-discard probe stranded one `LootHistoryExportWindow` per open. |
| `core/DebugLogSetup.lua` | The **`LibKa0s-DebugLog-1.0`** seam: `NS.DebugLog` and the global `NS.Debug` sink. Replaced the 359-line `modules/DebugLog.lua`. The window chrome is deliberately split: `applySkin` **is** passed, as a closure resolving `NS.Browser` at frame-build time (hoisting it into a load-time local silently loses the skin — `modules/Browser.lua` loads long after `core/`), while **`makeCloseButton` is still deliberately not passed**. The descriptor does carry **`addonName = addonName` beside `name = addonName`**: `name` seeds the frame globals, `addonName` is what the library builds a texture path from, and that one line turns the console's title strip into three icon controls (`close`, `copy`, `clear`) on both the console and its copy window. The window *edge* is shared across every Ka0s window; the *close control* on a library-drawn window is the library's — and since Core minor 6 the library's is this collection's `close` mark, so the two now match without either side overriding the other (standalone-windows; closed issue [LIBKA0S-19](https://github.com/tusharsaxena/LootHistory/issues/26), asserted in `tests/test_debuglog.lua`). |
| `core/PoolSetup.lua` | The **`LibKa0s-Pool-1.0`** seam: `NS.Pool` with `New`, `Acquire(pool, factory)`, `ReleaseAll(pool, before)` and `Counts(pool)`. TOC position is **conventional**: nothing resolves at load, and every `NS.Pool.New` call is inside a function (`modules/Analytics.lua:226`). It ended this addon's one genuinely wrong copy of a shared idea: the old chart pool hid its active widgets and dropped them, so the free list stayed empty and every `LayoutCharts` pass allocated a fresh frame per chart element — and frames are never destroyed in WoW. The `before` hook is not garnish: a host releasing a pool of panels releases each panel's own row pool first. Since LibKa0s v1.17.0 (Pool minor 3) `ReleaseAll` parks the active set **backward** — `Acquire` pops the free list from the end, so releasing the last rank first hands every widget back to the rank it already held instead of alternating that mapping on every render. `core/PoolSetup.lua`'s degraded fallback releases backward too: the copy that calls itself “the same pool, locally” is the one place the published contract must not quietly differ. |
| `core/LauncherSetup.lua` | The **`LibKa0s-Launcher-1.0`** seam: **`NS.Launcher`**, the minimap button and the broker plugin as **one** LibDataBroker object registered twice (launcher-§1). It replaced `B:SetupMinimap` / `B:RefreshMinimap` / `B:SetMinimapHidden` in `modules/Browser.lua`. The descriptor's `name` is the addon's **folder** name on both registrations — LibDBIcon keys the button by it — its `icon` is `media/logos/loothistory.logo.128.tga`, the same file the TOC's `## IconTexture` names (launcher-§4), and `minimap` is a **function** answering `db.global.minimap` rather than the table, because AceDB replaces any table captured at file load. **The two buttons are the library's** (Launcher minor 4, LibKa0s v1.58.0; launcher-§2, standard v2.67.0): **left-click opens the settings panel** (`openSettings`, `NS.Panel:Open`) in either state, and **right-click opens the options menu** — the client's context menu, titled with the label, with four checkboxes because this addon has all four states (ADDONS.md's row): **Enabled** (`isEnabled` = `not NS.AddonIsOff()`; `setEnabled(on)` runs the `/lh enable` or `/lh disable` handler), **Locked** (`isLocked` = `B:IsLocked`, the *Lock frame* row's `settings.locked`; `toggleLock` writes that row's path through `Schema:Set`, because this addon has no lock verb), **Test mode** (`isTestMode` = `BrowserTable.testMode`; `toggleTestMode` runs the `/lh test` handler) and **Show window** (`isWindowShown` = the History window's `IsShown`; `toggleWindow` runs the `/lh toggle` handler). The verb handlers are reached through a local `runVerb`, which looks the verb up in `NS.COMMANDS` at call time and calls its `entry[3]`, so every entry is the verb itself — feature-verb gate and chat line included — never a copy. While disabled the library grays the last three with "enable the addon first" and calls none of them. The retired `onClick`, `leftClickLabel` and `disabledLine` are no longer passed. The **status tooltip is the library's** too (Launcher minor 3, LibKa0s v1.57.0; launcher-§1): it draws on every hover, disabled included — `Ka0s Loot History  v<version>` (`NS.Version()`, the TOC's), `Enabled: Yes|No`, `Locked: Yes|No`, `Test mode: On|Off`, the addon's one line (`onTooltipShow`: the record count), then the fixed hints `Left-click: Open settings` and `Right-click: Options menu`. Every field is a function, asked on every show and every menu open. `Register()` runs from `addon:OnInitialize`, after `NS:InitDB`. **The Show window key binding** (launcher-§6) is created here too, **above** the degraded exit so it answers on a library-less install: the plain, hidden, non-secure `LootHistoryToggleWindow` Button (a permanent name: the root `Bindings.xml` clicks it by name), registered `AnyDown`, whose `OnClick` prints `NS.RefusalLine()` when the addon stands down and otherwise runs the same `/lh toggle` handler as **Show window** (`runVerb` moved above the exit with it); the file also sets `BINDING_HEADER_LOOTHISTORY = NS.BRAND` (the binding's category, so its own section in Options -> Keybindings), the binding's `BINDING_NAME_` label (*Toggle history browser*) and **`NS.BINDINGS`**, the one bindings table the General page's Keybindings tab draws (options-ui-§20). **No degradation stub** — unlike every other seam here, nothing in the addon calls into this module except `OnInitialize` and the `minimap.shown` row's `set`, and both already guard on `NS.Launcher`; a stub answering `IsShown`/`SetShown` would be a second copy of state that lives in `db.global.minimap`. No profile event and no reset replaces `db.global.minimap` (launcher-§3), so the button keeps the table it was handed at `Register` and nothing in this addon names LibDBIcon directly. |

## TOC load order

`LootHistory.toc` orders files by dependency, not alphabetically. Libraries first, then `locales/`, `core/` (Compat first), defaults, modules, and settings last.

**These positions are load-bearing**, each carrying a `LOAD-BEARING` comment in the TOC (toc-file-§5; `grep -c LOAD-BEARING LootHistory.toc` counts them):

- `core/ItemSetup.lua` and `core/MediaSetup.lua` sit **above `core/Constants.lua`**, which calls `NS.Item.QualityLabel` and reads `NS.MediaFont` (for `FONT_MONO`) at file load.
- `core/CoreSetup.lua` sits **below `core/Namespace.lua`** (`lib:New{ prefix = NS.PREFIX }` at load) and **above every file-scope `NS.Print` capture** (`modules/Browser.lua:5`, `settings/Schema.lua:5`, `settings/Slash.lua:4`); `core/DebugLogSetup.lua` sits **below `core/Constants.lua`** (`FONT_MONO`).
- `core/SkinSetup.lua` sits **below `core/CoreSetup.lua`** (its degraded `Shell` calls `NS.ApplySkin`) and **above `core/WidgetsSetup.lua`, every module and `settings/Schema.lua`**: it registers the skin owner and publishes `NS.Skin` and the two Appearance rows' `values` at file load, and Schema reads those values into its rows at load.
- `core/PerfSetup.lua` sits **below `core/LifecycleSetup.lua` and `core/EnvSetup.lua`** (its `lib:New` reads `NS.Lifecycle` and `NS.Version` at load) and **above every `local Perf = NS.Perf` upvalue** (`modules/Attribution.lua:18`, `modules/Collector.lua:4`, `modules/Reconciler.lua:16`). That is the one reason `core/LifecycleSetup.lua`'s position matters: nothing in it resolves at load.
- `defaults/Global.lua`, `defaults/Profile.lua` and `settings/OptionsSetup.lua` sit **above `settings/Schema.lua`**, which takes `NS.defaults.profile` as a file-scope local (`settings/Schema.lua:21`) and composes its Master controls tab through `NS.Options.MasterControls` at file load (options-ui-§15).
- `settings/Slash.lua` sits **below `settings/Schema.lua`**: the dispatcher is built at load with `commands = NS.COMMANDS`, which Schema assigns; above it, `:New` raises and `/lh` never registers.
- `settings/Panel.lua` sits **below `settings/Schema.lua`**: it reads `NS.Schema.MASTER_GROUP` and `NS.Schema.MasterAfterGroup` at file load.
- `core/Dispatch.lua` sits **above every module**: Attribution, AttributionOut, Collector and Reconciler call `NS.EventRow` / `NS.HookRow` at file load, and row order is TOC order. That is also why `modules/Collector.lua` sits directly below `modules/AttributionOut.lua` and above `modules/Reconciler.lua`: the rows then come out in the stand-up order (Attribution, AttributionOut, Collector, Reconciler; `core/LifecycleSetup.lua`).
- `core/SimSeam.lua` sits **straight after `core/Compat.lua`**: `Sim:NewSeam` wraps every `NS.Compat` member in place at file load, so a member added below it escapes the wrap (`NS.SimSeam:Unwrapped()`, asserted empty by `tests/test_sim_seam.lua`). The simulator's modules chain below it: `modules/SimWorld.lua` (registers its providers on `NS.SimSeam` at load) above `modules/SimDrivers.lua` (binds `NS.SimHost.World`) above `modules/SimScenario.lua` (binds both) above `modules/Sim.lua` (`Sim:New` at load, below every capture module and `core/Dispatch.lua`, above `settings/`) above `modules/SimPanel.lua` (calls `NS.Sim:AddListener` at load).
- In `modules/`: `modules/Escrow.lua` sits **below `modules/Reconciler.lua`** (it appends to the Reconciler's `SCAN_STEPS` / `PLAN_STEPS` / `COMMIT_STEPS` at load); `modules/Analytics.lua` and `modules/AnalyticsCharts.lua` sit **below `modules/AnalyticsFormat.lua`** (`Analytics.K` and the `Analytics._*` helpers, bound at load); `modules/BrowserWidgets.lua` sits **directly above `modules/Browser.lua`** (Browser binds its `B._dataset` and `B._options` builders at load); `modules/BrowserFilterBar.lua` sits **below `modules/Browser.lua`** (it binds `B._applyFilter` and its siblings at load); `modules/BrowserTableGroup.lua` sits **directly below `modules/BrowserTable.lua`** (it binds `BrowserTable._columnByKey` and `BrowserTable._groupColumn` at load); `modules/HoldingsTab.lua` and `modules/Timeline.lua` sit **below `modules/Browser.lua`** (each calls `NS.Browser:RegisterTab` at load), and `modules/Timeline.lua` also **below `modules/TimelineModel.lua`** (`TM.TOTAL`).

Everything else is **conventional**, and the TOC marks it so: `locales/`, the plain Core run (Constants, Namespace, State, Util, Ledger, LootHistory, Database), the Env, Widgets, Pool and Launcher seams, and every unannotated `modules/` file (one CONVENTIONAL line heads the group); none of them resolves a sibling at load.

Registers the skin owner `"LootHistory"` at **file load** (`Skin:RegisterOwner(addonName, { label = NS.BRAND, get = NS.SkinChoice, set = NS.WriteSkinChoice })`) and publishes **`NS.Skin = Skin:For("LootHistory")`**, the facade every surface paints through and reads its colors from. 15. `core/Dispatch.lua` — **one capture event table and one read-side hook table** (LootHistory#37, the simulator's host contract). `NS.EVENT_ROWS` is an ordered list of `{ event, owner, target, fn, unit? }`: `target` is `bus` (`NS.addon`), `out` (`Attribution.__outEv`), `ledger` (`Reconciler.__ev`) or `spell` (the player-only `RegisterUnitEvent` frame), and `fn(event, ...)` receives the client's full payload. `NS.HOOK_ROWS` is an ordered list of `{ name, owner, fn, tbl?, install? }`: a plain row hooks the global `name` through `Compat.HookSecure`, `tbl` makes it a `Compat.HookSecureMember` hook on that table, and `install` names a Compat installer with its own presence ladder (`HookUseContainerItem`). The modules append their rows at file load through `NS.EventRow` / `NS.HookRow` (the `R.SCAN_STEPS` precedent), so row order is TOC order: Attribution (nine bus rows, one spell row, five hooks), AttributionOut (six out rows, thirteen hooks), Collector (three bus rows), Reconciler (fourteen ledger rows). `NS.RegisterRows(owner, targetObj, targetKey)` registers an owner's rows through `NS.SafeRegisterEvent` / `SafeRegisterUnitEvent` and sets `row.registered` only on success; `NS.UnregisterRows(owner)` unregisters them by name and clears it; `NS.InstallHookRows(owner)` installs an owner's hooks, under the module's own once-per-session latch (`_hooked` / `_outHooked`), and marks `row.installed`. The one header **Defaults** button (options-ui-§5) is built lazily on first `OnShow` and is **page-wide** (options-ui-§13): it is the global reset, `CliResetAll`, which resets the whole profile — schema rows, the three id-lists, the auction cascade, the saved view and the window geometry. It no longer re-centers the window — **Reset position** is its own button on the Master controls tab. Writes route through `NS.Schema:Set` (schema rows) or `NS.Filters` (the lists); `P:Open` is combat-gated. See [settings-panel.md](settings-panel.md).
61. `settings/Profiles.lua` — `NS.ProfilesPage`: the **Profiles** subcategory (options-ui-§3). `Build` registers AceDBOptions' options table over `NS.db` with AceConfig and draws it with AceConfigDialog into an AceGUI group on a canvas made by `O.CreatePanel` (no Defaults button), through `O.SetRenderer` so the combat lock covers it; it answers nil, and the page is absent, when AceDBOptions, AceConfig or AceConfigDialog is missing. ## AceAddon lifecycle

1. **TOC file-load** as listed above. After load: `NS.Compat` / `NS.Constants` / `NS.State` / `NS.Util` are populated; `core/LootHistory.lua` has run `AceAddon-3.0:NewAddon` to promote `NS` in place (setting `NS.addon` / `NS.bus` and defining `NS.NewBusTarget`); `NS.defaults` is set; `NS.L` exists; `NS.Schema` (with `NS.COMMANDS`), `NS.Slash` (with its confirm dialogs registered) and `NS.Panel` exist; each module has published `NS.X = NS.X or {}` and defined its methods but **not** enabled — no module touches a WoW event/hook/frame API at file-load (so the headless test harness can load every file).
2. **`addon:OnInitialize`** (Ace lifecycle, fires on `ADDON_LOADED`; `LootHistory.lua:28-53`): `NS:InitDB` builds the AceDB instance and runs `NS:RunMigrations` (the idempotent seam; the `MIGRATIONS` array ships thirteen steps carrying the stamp from the declared `0` floor to the current shape `14`: v9 moves every setting into the `Default` profile before anything reads a profile, v10 lifts `retentionDays` back to `db.global`, and v11-v14 are the timeline ledger's (the ledger stores, Show transfers on, holder moves as a loss and a gain, per-tab saved views) — see [schema.md](schema.md)); `NS.ApplySkinChoice` then applies the active profile's skin (`core/SkinSetup.lua`; the owner has worn Ka0s Default since it registered at file load); `NS.Schema:Register` runs boot validation (the library's `Validate`: every row well-formed, and every schema path resolving against the defaults); `NS.Slash:Register` binds `/lh` + `/loothistory`; `NS.Panel:Register` registers the Blizzard canvas categories (deferred content — panels render lazily on first `OnShow`); `NS.Launcher:Register` builds the one LibDataBroker object and hands it to LibDBIcon (launcher-§1), last and **after `NS:InitDB`**, because that is the moment `db.global.minimap` exists. Last of all, `NS.BindLifecycle` (`core/LifecycleSetup.lua:301`) registers AceDB's three profile callbacks onto the one adopt path, `NS.OnProfileEvent` (`core/LootHistory.lua:99`), which needs `NS.db` to exist.
3. **`addon:OnEnable`** (`LootHistory.lua:131-137`): calls `NS.StandUp` (`core/LifecycleSetup.lua:207`), the ONE place the registrations live and the same function the latch calls on the way back up. It registers `PLAYER_ENTERING_WORLD` → `OnEnterWorld`, then enables the modules in order — `Attribution:Enable` (peripheral event registrations + read-side hooks), `Collector:Enable` (`CHAT_MSG_LOOT` + the `SettingsChanged` upvalue-refresh subscription), `Browser:Enable` (bus subscriptions) and `Analytics:Enable` (the Insights pane's bus subscriptions, lifted out of `BuildCharts` so a stand-down can drop them and a stand-up restore them). `OnEnable` then sets the `disabled` hold from the stored switch (`NS.Lifecycle:Set(NS.HOLD_DISABLED, NS.AddonIsOff())`), so on a disabled install the latch stands the addon straight back down. `Filters` is data-only (no `Enable`); `BrowserTable` has **no** `Enable` — it attaches lazily when the Browser first builds its pane; `DebugLog` likewise builds its frame lazily. `Panel` and `Slash` do their work in `OnInitialize`, not here.
4. **`addon:OnEnterWorld`** (`LootHistory.lua:142-174`): guarded to run once per session (`NS.State.cleanupDone`). Schedules `Database:PruneOld` via `NS.After(5, …)` — cancelable, so a stand-down inside those five seconds drops it — so retention cleanup lands 5 s after the login/zone spike rather than during it, and rides the same deferral for `Database:RepairBoundStates` — which runs again at +20 s, because it needs an item cache that is cold at login and the first pass is what warms it; that +20 s deferral also sets `NS.State.loginSettled`, which the simulator waits for. `PruneOld` drops records older than `settings.retentionDays` (0 = keep Always) by rebuild-and-swap and fires `HistoryChanged` when it removed any; a prune with nothing to drop touches nothing and fires nothing.
