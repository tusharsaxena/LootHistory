# Module map

Where each responsibility lives in the source tree, plus the TOC load order and the AceAddon lifecycle hooks. `LootHistory.toc` is the source of truth for load order — match this map to it before editing. 23 source files across `core/`, `defaults/`, `locales/`, `settings/`, `modules/`; the internal-only terms **Collector** (capture) and **Browser** (view) are used throughout.

## TOC load order

`LootHistory.toc` orders files by dependency, not alphabetically. Libraries first, then `locales/`, `core/` (Compat first), defaults, modules (Attribution and Filters before Collector), and settings last.

1. `libs/` — vendored LibStub, CallbackHandler-1.0, AceAddon-3.0, AceEvent-3.0, AceTimer-3.0, AceConsole-3.0, AceDB-3.0, AceGUI-3.0, LibSharedMedia-3.0, LibDataBroker-1.1, LibDBIcon-1.0, and **LibKa0s** (`libs\LibKa0s\LibKa0s.xml`, last in the block — four of its five majors resolve `LibKa0s-Core-1.0` before registering). Committed in-tree (Ka0s Standard v2.0.0 — vendoring is mandatory; `.pkgmeta` externals are forbidden). Don't edit.
2. `locales/enUS.lua` — `NS.L` with a metatable that returns the key itself, so English strings work untranslated and missing keys never error. The addon ships English-only: no user-facing string routes through `NS.L` yet (an accepted scope decision, `enUS.lua:7-11`); the seam is kept for a future localization pass. Loads early (before `core/`) so `NS.L` exists for everything after it.
3. `core/Compat.lua` — **loads first** of `core/`. Hangs `NS.Compat` (the private namespace `NS` is the second file vararg, not a global) and populates every deprecated/varying API shim: `GetPlayerMapID`, `GetActiveKeystoneLevel`, `HookUseContainerItem` / `ContainerItemHasLoot`, `HookGetQuestReward` / `CurrentQuestID`, `IsSpellTargeting`, `GetSpellName`, `GetMailHeader` / `IsAuctionHouseMail`, `GetZone`, `DecodeGUID` (+ `UNIT_KINDS`), `QualityFromLink` / `QualityLabel`, `GetItemInfo`, `ItemNameQuality`, `LoadItem`, `ScanBound`, `BindState` / `ItemBindState` / `BestBound` (the two warbound signals and their merge), `GetItemExtras`, `GetAddOnMetadata`. Each is gated by a direct `C_*`/global presence check (`Compat.lua:5-7`) — no `WOW_PROJECT_ID` branching — so anything later can rely on `NS.Compat` existing.
4. `core/Constants.lua` — exposes `NS.Constants` with the `SourceType` enum (stable string keys = the export contract; `Constants.lua:8-13`), `SourceOrder` / `SourceLabel`, the `SOURCE_IMPLEMENTED` mute-UI gate (`Constants.lua:37-41` — every source now has a live capture path, so all are offered), `ITEMCLASS_QUEST` (locale-independent quest-item class, `Constants.lua:44`), `CONTEXT_TTL` (1.5 s), the quality/retention/source option tables, and `FONT_MONO`. Publishes `NS.SourceType` / `NS.Confidence` aliases.
5. `core/Namespace.lua` — sets `NS.name`, `NS.version` (`"1.2.0"`, `Namespace.lua:5`), and `NS.PREFIX` (the cyan `|cff00ffff[LH]|r` chat tag, slash-commands-§4). Modules still self-publish idempotently; nothing else wired here.
6. `core/State.lua` — `NS.State`, the runtime-only mutable state: `lootContext` (the single-slot attribution stamp), `encounter` / `keystone` (instance context), the session flags `cleanupDone`, `debug`, and `testRecords`. Reset every load — never persisted to SavedVariables.
7. `core/Util.lua` — pure helpers: `PlayerKey` (`Name-Realm`), `SplitPath`, `FormatClock` / `FormatDate` / `FormatMoney` / `FormatBytes`, `RangeFrom` (date-range key → `from` epoch, used by the shared filter bar's Date dropdown), and `BuildLootPatterns` / `ParseSelfLoot` (compile the localized loot global-strings once and parse a `CHAT_MSG_LOOT` line into link + quantity). The shared **secret-safe chat printer** used to live here too; it is `LibKa0s-Core-1.0`'s now — see 8 below.
8. `core/CoreSetup.lua` — the **`LibKa0s-Core-1.0`** seam. Publishes `NS.Print` / `NS.Format` (the prefixed, secret-safe chat printer, built with `prefix = NS.PREFIX` and the default single-space separator), `NS.Util.print`, `NS.SafeToString` and `NS.IsConcatSafe`. Four load-order constraints pin it here and they are all real: **after** `core/Namespace.lua` (which defines `NS.PREFIX`, so the plain string form works and the function form is unnecessary), **after** `core/Util.lua` (which publishes `NS.Util`), **before** `core/LootHistory.lua` (whose AceConsole reclaim reads `NS.Util.print` back over `NS.Print` — publishing to BOTH keys is what makes that reclaim restore the library printer rather than silently undo the seam), and **before** the four files that capture `local print = NS.Print` at file scope (`modules/Browser.lua`, `settings/Schema.lua`, `settings/Slash.lua`, `settings/Panel.lua`). It also publishes **`NS.LIBKA0S_MISSING`**, the one cause clause every LibKa0s seam in this addon appends its own consequence to — a cross-file contract three other files depend on, set OUTSIDE the `if not lib` branch because they read it on both paths. It also publishes **`NS.ApplySkin`** — `Core.ApplySkin` on a working install, and its own pre-library copy of the same edge in the degraded branch — which is the seam `modules/Browser.lua`'s `B:ApplySkin` delegates to, so the window edge is `Core.SKIN`'s and is not restated in this addon (standalone-windows). Only `Core.MakeCloseButton` is still declined: the History browser closes with a 24×24 class-colored glyph, not Core's 18×18 ×.
9. `core/DebugLogSetup.lua` — the **`LibKa0s-DebugLog-1.0`** seam, replacing the 359-line `modules/DebugLog.lua` outright. Publishes `NS.DebugLog` (the console window, the copy window, both formatters, the buffer and the enable seam) and rebinds the global sink `NS.Debug`. Loads after `core/Constants.lua` (the descriptor reads `FONT_MONO` at `:New` time) and before `core/Database.lua` (whose migrations call `NS.Debug` during `InitDB`). The window *edge* stays this addon's through the `applySkin` descriptor hook, passed as a **closure** that resolves `NS.Browser` at frame-build time — hoisting that lookup into a local here would silently lose the skin, because `modules/Browser.lua` loads much later. **`makeCloseButton` is deliberately not passed**: the close control on a library-drawn window is the library's, so the console and the copy window wear Core's thin 18×18 ×, while this addon's 24×24 class-colored glyph stays on the windows it belongs to (standalone-windows; [pending/LEDGER.md](pending/LEDGER.md) LIBKA0S-19, asserted in `tests/test_debuglog.lua`).
10. `core/LootHistory.lua` — the AceAddon bootstrap. `AceAddon:NewAddon(NS, addonName, "AceEvent-3.0", "AceTimer-3.0", "AceConsole-3.0")` promotes `NS` in place (no `_G.LootHistory` rebind — the namespace stays private) and sets `NS.addon` / `NS.bus`. Defines `NS.NewBusTarget()` — the fresh-AceEvent-target factory every message consumer must use so two consumers can't clobber each other on the shared bus (`LootHistory.lua:20-26`; see [message-bus.md](message-bus.md)). Defines the three lifecycle hooks (below).
11. `core/Database.lua` — defines `NS:InitDB` (`AceDB-3.0:New("LootHistoryDB", NS.defaults, true)` — account-wide) and `NS:RunMigrations` (reads/writes `db.global.schemaVersion` and walks the module-level `MIGRATIONS` array, `Database.lua:19-117`, whose v1→v2 entry strips the retired `viaWhitelist` field, `Database.lua:23-29`), then `NS.Database` with the read/write path: `History` (the raw array) / `ActiveHistory` (the test-mode-aware read seam behind Query/Stats — blacklist/whitelist filtering is point-in-time, decided at capture, so reads never hide a stored row), `Count`, `Add` (fires `RecordAdded`), `QueryList` / `Query`, `Export` (the v2 export contract), `Stats` (the single O(n) pass all Insights widgets consume), `Delete` / `Purge` / `PruneOld` (all fire `HistoryChanged`), `RepairBoundStates` (the deferred warbound-state split, armed by `NS:ArmBoundRepair`), and `StorageStats`. Does not create the DB at file-load.
12. `defaults/Global.lua` — `NS.defaults.global`: `schemaVersion = 1`, `history = {}`, `blacklist = {}` / `whitelist = {}` (the item-id filter lists), `currencyBlacklist = {}` (the currencyID-keyed list), the `settings` table (enabled, qualityThreshold, excludeQuestItems, recordCurrency, excludedSources, retentionDays, windowScale, window, and the `auction` cascade), and `minimap = { hide = false }`. History, lists and settings all live under `.global` (account-wide); debug is deliberately NOT here (session-only). See [schema.md](schema.md).
13. `modules/Attribution.lua` — **loads before Filters/Collector.** The source-resolution engine (`NS.Attribution`). `Stamp` writes the single-slot `State.lootContext` (fresh for `CONTEXT_TTL`, not cleared on consume — one loot window emits many lines); `Consume` reads it or falls back to `OTHER`/`INFERRED`. `ResolveLootSource` maps a loot-slot GUID + instance state → source + detail (Creature→KILL, GameObject→MPLUS/CONTAINER, Item→CONTAINER). `Attribution:Enable` (called from `OnEnable`, never at file-load) registers the peripheral stampers: LOOT_OPENED, ENCOUNTER/CHALLENGE_MODE, TRADE_ACCEPT_UPDATE, QUEST_TURNED_IN, a player-only `RegisterUnitEvent` frame for deconstruct spell-success, and `hooksecurefunc` hooks for vendor buy / mail take / container use / quest reward. See [data-flow.md](data-flow.md).
14. `modules/Filters.lua` — `NS.Filters`, the blacklist/whitelist item-id lists (issue #14) **plus the currencyID-keyed currency blacklist**. **Loads before Collector.** Copy-on-write `AddBlacklist` / `AddWhitelist` (each drops the id from the sibling list) / `RemoveBlacklist` / `RemoveWhitelist` write a fresh table to `NS.db.global.{blacklist,whitelist}` and re-cache the Collector + fire `HistoryChanged` (the browser re-queries); `AddCurrencyBlacklist` / `RemoveCurrencyBlacklist` (blacklist-only, no sibling) manage `NS.db.global.currencyBlacklist`; `Blacklist` / `Whitelist` / `CurrencyBlacklist` (the live id sets) / `SortedIDs` / `ParseItemID` / `ParseCurrencyID` (id from a number, link, or itemString) support the panel + right-click UIs. `ClearList` / `ClearAll` empty one or all lists (the Filters page's per-list **Clear all** and header **Defaults** buttons; `ClearAll` includes the currency list). Data-only — no `Enable`. An architecture-§5 carve-out from `Schema:Set`.
15. `modules/AuctionPrice.lua` — `NS.AuctionPrice`, the AH-price integration boundary. **Loads before Collector.** `GatherAll(itemLink, itemID)` resolves the live `settings.auction.capture` set into a per-provider fetch (Auctionator / TSM / OribosExchange), capturing **every** configured key — not just one — into a nested `provider → key → copper` map. Each provider fetcher is `pcall`-wrapped so a broken/absent addon degrades to `nil` and the gather continues to the next. `Pick(map)` is the separate read-time seam: it walks `settings.auction.priority` (an ordered cascade selection list) and returns `price, tag` for the first present key (both `nil` when the map is empty or nothing captured). Data-only — no `Enable`. Deliberately **outside** `core/Compat.lua` (Blizzard-API-only) — see Standards compliance in [ARCHITECTURE.md](ARCHITECTURE.md).
16. `modules/Collector.lua` — `NS.Collector`, the acquisition path. `ShouldRecord` is the pure, point-in-time gate: a blacklisted id is an absolute veto (the item is never written); otherwise the item records if it passes the normal gate (quality / excluded-source / quest-item, keyed on the locale-independent `ITEMCLASS_QUEST`), or — failing that — if it is whitelisted, in which case it returns `true, "whitelist"` and the row is written as a plain record with no marker of how it got in (later whitelist edits never revisit it). `BuildRecord` assembles the record, including the `auctionPrice` map stamped by an `AuctionPrice:GatherAll` call. `OnChatMsgLoot` parses the self-loot line, consumes the attribution context, gates (passing the item id + the cached lists), gathers item/zone extras, gathers the AH prices, and calls `Database:Add`. `OnChatMsgCurrency` handles `CHAT_MSG_CURRENCY` with a slimmer gate — the `recordCurrency` master toggle, the per-source mute list, and the currency blacklist (no quality/quest/itemID checks) — writing a `Type=Currency` row that reuses the same attribution context (a self-identifying "You are refunded" currency line attributes REFUND directly). `Collector:Enable` registers `CHAT_MSG_LOOT` + `CHAT_MSG_CURRENCY` and — on its own `NS.NewBusTarget()` — `Ka0s_LootHistory_SettingsChanged`, refreshing the hot-path upvalues (`enabled`/`qualityThreshold`/`excludedSources`/`excludeQuestItems`/`recordCurrency`/`blacklist`/`whitelist`/`currencyBlacklist`) rather than reading the DB per loot (Ka0s events-frames-taint-§7).
17. `modules/Browser.lua` — `NS.Browser`, the standalone window (Ka0s standalone-windows reference implementation). Owns the non-secure `LootHistoryWindow` frame (HIGH strata, movable/resizable, ESC via `UISpecialFrames`), the `ApplySkin` re-skin seam (which delegates the edge to `NS.ApplySkin`/`Core.SKIN`; the local `SKIN` table keeps only the tab colors and layout heights), window position/scale persistence to `NS.db.global.settings.window` (an architecture-§5 carve-out from `Schema:Set`), the History/Insights tab strip (lazy pane build), the **shared singleton filter bar + footer** (multi-select dropdowns Bound / Quality / Type / SubType / Source / Zone / Character; `CurrentFilter` feeds both the table and the Insights charts — issue #13), the saved-view logic and session-only current-player character scope, the **tab-aware `Export` button** (`OpenExport` → loot rows on History, analytics on Insights — issue #15), and the LibDataBroker launcher + LibDBIcon minimap button. Exposes `MakeDropdown` / `GetWindow` for `Export` to reuse. `Browser:Enable` subscribes to `SettingsChanged` / `HistoryChanged` / `RecordAdded` on its own bus target and calls `SetupMinimap`. See [browser.md](browser.md).
18. `modules/BrowserTable.lua` — `NS.BrowserTable`, the virtualized pooled-row History table. Defines the `COLUMNS` model (Character always last; SubType after Type), the filter→sort→group→slice→bind pipeline over `Database:QueryList(CurrentRecords, filter)`, `OrderedFilteredRecords` (the on-screen order the Export Current-View dataset serializes), a `FauxScrollFrame` + row pool (never one frame per record, Ka0s standalone-windows), collapsible group headers, the class-icon / bound-lock markup, the right-click row menu (link / **blacklist** / delete), and the deterministic-PRNG synthetic dataset for `/lh test` (`ToggleTestMode` publishes `NS.State.testRecords`, so both the table and Insights render off the same fake data).
19. `modules/Export.lua` — `NS.Export`, the export modal (`Export:Open`). Builds a small skinned window with a Data Set dropdown (All Data / Current View) and an Export-to-CSV button, reusing `Browser:MakeDropdown` / `ApplySkin` / `MakeCloseButton` and centering on the History window. Driven by a per-open `config = { title, providers, csv }` — the invoking tab supplies the window header ("Export History" / "Export Insights"): `CSV` serializes loot rows (record fields + derived `date`/`time`/human `quality`/`vendorPrice` beside `*Raw` columns, the computed `auctionPrice`/`auctionPriceRaw`/`value`/`valueRaw`/`auctionSource` columns from `NS.AuctionPrice:Pick` + `NS.Util.RecordValue`, one raw `auc_<provider>_<key>` column per `NS.Constants.AUCTION_KEYS` entry, + `wowheadLink` last) for the History tab; `InsightsCSV` serializes a `Database:Stats` result into a sectioned analytics CSV for the Insights tab (issue #15). `WowheadLink` builds a `wowhead.com/item=…?bonus=…` URL from the item's bonus IDs; output opens in Export's own copy window. Called directly by the Browser — no bus message.
20. `modules/Analytics.lua` — `NS.Analytics`, the Insights tab, split by two dividers into a **LOOT** block and a **CURRENCY** block. Attaches to the Browser's Insights pane, builds stat/highlight cards + the **LOOT** breakdowns (items-only: source, value, quality, item type, bound type, each with a per-character stacked companion; per-day + value-per-day strips; hour-of-day; weekday; top zones/items/value lists) and the **CURRENCY** breakdowns (Currency Collected, Currency by Type × Source, Currency by Character × Type, currency-per-day — shown only when the range has currency events), all off a single `Database:Stats(filter)` pass **scoped by the browser's shared filter** (`Browser:CurrentFilter`, issue #13 — no range selector of its own). `byKeystone`/`byConfidence`/`currencyBySource` are still computed but feed only the Export (their in-dashboard charts were removed). Widgets are pooled and re-laid-out on resize; `BuildCharts` subscribes to `RecordAdded` / `HistoryChanged` on its own bus target for live refresh.
21. `settings/Schema.lua` — `NS.Schema` (alias `S`): one row per setting (`S.Schema`, `Schema.lua:23-113`) driving AceDB defaults, panel widgets, and the slash CLI. `S:Set(path, value)` is the single user-setting write seam — validate → deep-copy → write to `NS.db.global` → `onChange` (`Schema.lua:160-175`); the deep-copy stops a reset from aliasing the DB to a shared default table. Also owns `NS.COMMANDS`, the slash dispatch/help table (`Schema.lua:213-245`). `debug` is intentionally not a Schema row. Settings load **after** modules — nothing in `modules/` reads `NS.Schema`/`NS.COMMANDS` at file-load, only inside functions at runtime.
22. `settings/Slash.lua` — `NS.Slash`, and the **`LibKa0s-Slash-1.0`** seam. Registers `/lh` and `/loothistory` via AceConsole and hands the library the positional `NS.COMMANDS` triples; the dispatcher, the help header and rows, `LandingRows`, `BuildListLines`, `CliGet` / `CliSet` / `CliList` / `CliReset` / `CliResetAll` / `CliVersion` and the type-aware value parser are all the library's. What stays this addon's: the purge / reset-everything / list-clear `StaticPopupDialogs` confirm dialogs registered at file-load, the `ResetEverything` full wipe behind the panel's **Reset Everything** button (deliberately not called "Reset All", which is what the lesser `/lh resetall` verb does), the `CliResetAll` wrapper that also clears the three id-lists (a storage carve-out with no schema row, so the library's row walk cannot see them), and `Sl.FormatSchemaValue` — passed as the descriptor's `format` hook, holding the one branch the library has no type for (`type = "table"`, which would otherwise fall through to Core's `SafeToString` and render a plain settings value as `<secret>`). See [slash-dispatch.md](slash-dispatch.md).
23. `settings/OptionsSetup.lua` — the **`LibKa0s-Options-1.0`** seam, and where every declined surface is written down. Publishes `NS.Options`: the Blizzard canvas shell, the breadcrumb header, the lazy Defaults button, the page registry, `EnsureScroll` plus the always-shown scrollbar patch, `Section` / `AddSpacer` / `AttachTooltip`, the five widget makers, the two-column flow engine, `SetRenderer`, the two refresh tiers and `OpenOptionsPanel`. The descriptor points `get` / `set` / `applyDefault` at `NS.Schema`, maps `rowsForPage` onto the schema's `group` (this addon's section headings *are* its pages), stashes AceGUI as `NS.AceGUI` for the page file, and late-binds `buildMain` through `NS.Panel.BuildMain`. Must load **before** `settings/Panel.lua`, which takes `NS.Options` as a file-scope upvalue.
24. `settings/Panel.lua` — `NS.Panel`. Registers the parent `Settings.RegisterCanvasLayoutCategory` (a logo + tagline + slash-command landing page) plus three subcategories: `General` (the schema settings), `Filters` (blacklist/whitelist item-id management — a custom non-schema page: add-by-id/link box + a live list with Remove per id, driven by `NS.Filters`), and `AH Price` (the master `enabled` schema toggle + a **frame-light unified price table**, `buildAuctionTable`: FontString text columns + reused row slots so it stays ~50 frames — the previous ~213-frame page froze the Settings canvas on tab-transition; per-row Enabled checkbox writes the single collect-and-rank `settings.auction.capture` flag, reorder arrows drive `settings.auction.priority`). The canvas shell, the breadcrumb header, the lazy Defaults button, the scroll + always-shown-scrollbar patch (Ka0s options-ui-§10), the section headings and the two-column flow engine are all `LibKa0s-Options-1.0`'s now (see 23); this file supplies the page builders, the live History stats + Purge section, and the two widgets the library has no maker for. Three of the four pages declare themselves through `O.SetRenderer`, which owns *when* they draw — first show, and again after a structural refresh marked them dirty while hidden. Structural refreshes are split from scalar ones (options-ui-§11): scalar widgets re-sync in place every `OnShow`, structural list rebuilds are gated to first-paint / on-screen edit / a dirty flag. Two surfaces are deliberately host-drawn: the inverted muted-source picker (none of the library's five makers, emitted from `afterGroup` so it lands exactly where the generic path used to put it) and the AH Price page's own `OnShow` (its eleven pooled row slots of raw FontStrings are parented to an AceGUI SimpleGroup's frame, and a renderer's `ClearScroll` would release that group and orphan them). Both are recorded in [pending/LEDGER.md](pending/LEDGER.md). Each subcategory carries a header **Defaults** button (options-ui-§5), built lazily on that panel's first `OnShow` so the shared AceGUI widget is created after skinning addons have hooked `RegisterAsWidget` — never at registration time: General's runs the non-destructive `CliResetAll` (and recenters the window); Filters' clears both id-lists (confirm-gated → `NS.Filters:ClearAll`); AH Price's resets its schema rows + priority order. Writes route through `NS.Schema:Set` (schema rows) or `NS.Filters` (the lists); `P:Open` is combat-gated. See [settings-panel.md](settings-panel.md).

## AceAddon lifecycle

1. **TOC file-load** as listed above. After load: `NS.Compat` / `NS.Constants` / `NS.State` / `NS.Util` are populated; `core/LootHistory.lua` has run `AceAddon-3.0:NewAddon` to promote `NS` in place (setting `NS.addon` / `NS.bus` and defining `NS.NewBusTarget`); `NS.defaults` is set; `NS.L` exists; `NS.Schema` (with `NS.COMMANDS`), `NS.Slash` (with its confirm dialogs registered) and `NS.Panel` exist; each module has published `NS.X = NS.X or {}` and defined its methods but **not** enabled — no module touches a WoW event/hook/frame API at file-load (so the headless test harness can load every file).
2. **`addon:OnInitialize`** (Ace lifecycle, fires on `ADDON_LOADED`; `LootHistory.lua:28-35`): registers the JetBrains Mono font with LibSharedMedia; `NS:InitDB` builds the AceDB instance and runs `NS:RunMigrations` (the idempotent seam; ships the v1→v2 migration that strips the retired `viaWhitelist` field and bumps the stamp to `2`); `NS.Schema:Register` runs boot validation (every schema path must resolve against the defaults); `NS.Slash:Register` binds `/lh` + `/loothistory`; `NS.Panel:Register` registers the Blizzard canvas categories (deferred content — panels render lazily on first `OnShow`).
3. **`addon:OnEnable`** (`LootHistory.lua:37-45`): registers `PLAYER_ENTERING_WORLD` → `OnEnterWorld`, then enables the modules in order — `Attribution:Enable` (peripheral event registrations + read-side hooks), `Collector:Enable` (`CHAT_MSG_LOOT` + the `SettingsChanged` upvalue-refresh subscription), and `Browser:Enable` (bus subscriptions + `SetupMinimap`). `Filters` is data-only (no `Enable`); `BrowserTable` and `Analytics` have **no** `Enable` — they attach lazily when the Browser first builds their pane (`Analytics` subscribes to the bus in `BuildCharts`); `DebugLog` likewise builds its frame lazily. `Panel` and `Slash` do their work in `OnInitialize`, not here.
4. **`addon:OnEnterWorld`** (`LootHistory.lua:48-62`): guarded to run once per session (`NS.State.cleanupDone`). Schedules `Database:PruneOld` via `C_Timer.After(5, …)` so retention cleanup lands 5 s after the login/zone spike rather than during it, and rides the same deferral for `Database:RepairBoundStates` — which runs again at +20 s, because it needs an item cache that is cold at login and the first pass is what warms it. `PruneOld` drops records older than `settings.retentionDays` (0 = keep Always) by rebuild-and-swap and fires `HistoryChanged`.

## External dependencies

All vendored under `libs/` and pulled in by `LootHistory.toc` (Ka0s Standard v2.0.0 — vendoring is the suite-wide rule; do not switch to `.pkgmeta` externals): LibStub, CallbackHandler-1.0, AceAddon-3.0, AceEvent-3.0, AceTimer-3.0, AceConsole-3.0, AceDB-3.0, AceGUI-3.0, LibSharedMedia-3.0, LibDataBroker-1.1, LibDBIcon-1.0, and **[LibKa0s](https://github.com/tusharsaxena/LibKa0s)** — the Ka0s-owned shared library, of which this addon wires four majors (`Core`, `DebugLog`, `Slash`, `Options`) and declines the fifth (`Perf`; see [pending/LEDGER.md](pending/LEDGER.md), LIBKA0S-17). LibKa0s is vendored **whole-folder**, never file by file: four of its five majors resolve `LibKa0s-Core-1.0` before registering and refuse outright against an older minor, so a per-file copy is how cross-major skew gets manufactured. `tests/_kit/` is the same library's test harness, vendored under `tests/` (never `libs/`, which is the ship payload) — see [testing.md](testing.md#the-vendor-gate) for the four diffs that keep both copies honest. LibSerialize / LibDeflate are **not** vendored and there is no plan to add them — export is CSV-only (see [scope.md](scope.md)), so nothing needs a serialized/compressed share string. The `## OptionalDeps` line lists the same set so a shared standalone copy is used when present. `LootHistory.toc`'s `## Interface: 120007` targets Midnight (12.0.7).
